# Before Objects
Let's imagine programming without objects.
Suppose you're writing a music application.

You need a song.

Without objects, you might have:

song_name = "Believer"
song_duration = 204
song_artist = "Imagine Dragons"

play_song(song_name)
pause_song(song_name)
stop_song(song_name)

Now you create another song.

song2_name = "Perfect"
song2_duration = 263
song2_artist = "Ed Sheeran"

play_song(song2_name)

As your application grows, everything becomes harder to manage.

The data and the operations that belong together are scattered.

## The Problem 
The song's information is here:

song_name
song_artist
song_duration

The actions are somewhere else:

play_song()

pause_song()

stop_song()

Nothing groups them together.

Imagine this with thousands of models, tokenizers, datasets, optimizers, and configuration objects.

It would become chaotic.

The Solution: Objects

Objects group together:

State (data)
Behavior (operations)

Instead of:

song_name
song_duration
song_artist

Think:

Song

├── name
├── artist
├── duration
│
├── play()
├── pause()
└── stop()

Everything related to one song lives together.

What exactly is an object?

Definition

An object is a self-contained entity in memory that bundles together data (state) and the operations (behavior) that act on that data.

That's the formal definition.

Let's make it intuitive.

Real-world analogy

Imagine your phone.

It has information:

Battery = 82%

Brightness = 70%

Volume = 40%

It also has actions:

Increase volume

Open camera

Lock screen

Restart

Notice something?

You don't call:

increase_volume(phone_volume)

You simply tell the phone:

Phone.increase_volume()

The phone already knows how.

Python objects work exactly like this.

Python example
name = "Dedeepya"

What did Python create?

Not just text.

It created a String Object.

That object contains:

State

"Dedeepya"

Behavior

upper()

lower()

replace()

split()

strip()

You can ask it to do things because it owns those behaviors.

Another example
numbers = [10, 20, 30]

The list object contains:

State

10
20
30

Behavior

append()

extend()

sort()

remove()

pop()

clear()

The data and the operations live together.

Why is this brilliant?

Because now everything can be treated the same way.

Whether it's:

an integer,
a string,
a list,
a neural network,
a tokenizer,
or a model,

Python says:

"It's an object."

This consistency is one of Python's greatest strengths.

Now connect this to ML

Suppose you load a model.

model = AutoModelForCausalLM.from_pretrained(...)

Many beginners think:

"model is a neural network."

That's true.

But from Python's perspective:

It's an object.

Inside that object is data like:

Weights

Configuration

Device

Dtype

Layers

And behaviors like:

forward()

generate()

eval()

train()

save_pretrained()

state_dict()

So when you call:

model.generate(...)

you're not calling a random function.

You're asking the model object to perform one of its behaviors.

Why every ML framework uses objects

Imagine Hugging Face didn't use objects.

Instead of:

model.generate(tokens)

you might have:

generate(model_weights,
         model_config,
         device,
         tokenizer,
         tokens,
         ...)

Every call would require passing many related pieces around.

By keeping them inside the model object, the API becomes cleaner, easier to use, and less error-prone.

The mental model

Whenever you encounter an unfamiliar library, don't think:

"I need to learn another API."

Think:

"Someone has given me an object."

Then ask:

What state does this object hold?
What behaviors does it provide?
How can I inspect both?

## Python Objects
### What is it?
- An object is a self-contained entity in memory that combines state (data) and behavior (methods).
Why does it exist?
- To keep related data and operations together, making programs easier to design, use, and maintain.

Mental Model

Think of an object as a smart device. It stores information about itself and knows what operations it can perform.

Key Ideas
Everything in Python is an object.
Objects contain state and behavior.
Variables are names that refer to objects.
ML frameworks like PyTorch and Hugging Face are built around objects.
Understanding objects makes unfamiliar libraries much easier to explore.
Example
numbers = [10, 20, 30]

numbers.append(40)
numbers.sort()

Here, numbers is a list object. The list stores data and provides methods like append() and sort().

Where will I see this?
PyTorch: nn.Module, Tensor, Optimizer
Hugging Face: Model, Tokenizer, Config
Your work: SDK client objects, model objects, request/response objects
Why does this matter?

If you understand objects, you don't have to memorize every framework. You can inspect, understand, and work with any object systematically.

Quick Summary
Objects = State + Behavior.
Variables point to objects.
Everything in Python is an object.
Frameworks expose objects.
Learn to understand the object, not just the API.

That shift in thinking is the foundation of this entire course.
