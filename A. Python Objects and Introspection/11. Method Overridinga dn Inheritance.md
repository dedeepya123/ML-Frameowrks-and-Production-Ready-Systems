Lesson 11 – Method Overriding & super()
Goal

By the end of this lesson, you'll understand:

What method overriding is.
Why it exists.
What super() does.
Why PyTorch models override forward().
Why Hugging Face models override methods from base classes.
Step 1 – Let's start with a problem

Suppose we have:

class Animal:

    def speak(self):
        print("Some sound")

Now:

class Dog(Animal):
    pass

Question:

What happens when we do:

dog.speak()

Answer:

Some sound

Because Dog inherited speak() from Animal.

But...

Dogs don't make "Some sound."

Dogs bark.

Cats meow.

Cows moo.

So inheritance alone isn't enough.

We need a way for the child to replace the parent's version.

Step 2 – Method Overriding

Instead of accepting the parent's implementation:

class Dog(Animal):

    def speak(self):
        print("Woof")

Now think carefully.

Does Dog remove inheritance?

No.

Dog still inherits everything else:

eat()
sleep()
walk()

It simply says:

"For speak(), I have my own implementation."

This is called method overriding.

Mental Picture
Animal

eat()

sleep()

walk()

speak()  ---> "Some sound"

          ▲
          │
      inherited

Dog

eat()      ✓ inherited

sleep()    ✓ inherited

walk()     ✓ inherited

speak()    ---> "Woof"   (overridden)

Notice something beautiful.

The child reuses most of the parent and changes only what needs to change.

Why is this powerful?

Imagine there are 100 methods in the parent.

Without overriding, the child would need to rewrite all 100.

With overriding:

Reuse 99 methods.
Replace only 1.

That's elegant software design.

Step 3 – A Real-Life Analogy

Think of a company.

Every employee has:

an ID card
email
office access

Those come from the company.

But each employee has a different job.

A software engineer writes code.

A designer creates mockups.

An HR manager conducts interviews.

Same company.

Different responsibilities.

Inheritance provides the common capabilities.

Overriding customizes the specific behavior.

Step 4 – Where PyTorch uses this

Suppose you create your own model.

class MyModel(nn.Module):

Why inherit from nn.Module?

Because nn.Module already provides:

parameter registration
train()
eval()
state_dict()
device handling

But every model computes differently.

So your model overrides:

def forward(self, x):
    ...

Notice the pattern.

nn.Module

↓

Provides common infrastructure

↓

MyModel

↓

Overrides forward()

This is exactly method overriding.

Hugging Face Example

Imagine:

class GemmaForCausalLM(PreTrainedModel):

PreTrainedModel already knows how to:

save models
load models
manage config

But Gemma computes tokens differently from Llama.

So Gemma overrides methods like:

forward(...)

while still inheriting everything else.

Again:

PreTrainedModel

↓

Common functionality

↓

GemmaForCausalLM

↓

Overrides model-specific behavior
Step 5 – What is super()?

Now another interesting problem.

Suppose the parent does something important.

class Animal:

    def speak(self):
        print("Animal speaks")

Now Dog wants to:

keep the parent's behavior
add its own behavior

Without super(), you'd have to duplicate the parent's code.

That's not ideal.

The Solution
class Dog(Animal):

    def speak(self):

        super().speak()

        print("Woof")

Think of super() as saying:

"Call the parent class's implementation first."

Then continue with the child's extra work.

Mental Model

Imagine a restaurant.

The head chef prepares the base pizza.

Then each branch adds its own toppings.

Parent

↓

Prepare Base Pizza

↓

Child

↓

Add Special Toppings

The child doesn't remake the entire pizza.

It builds on the parent's work.

That's what super() is for.

Where you'll actually see super()

In PyTorch:

class MyModel(nn.Module):

    def __init__(self):

        super().__init__()

This is everywhere.

Why?

Because nn.Module has important initialization logic.

When you write:

super().__init__()

you're saying:

"Before doing my own initialization, let nn.Module initialize itself properly."

If you skip it, many features of nn.Module won't be set up correctly.

Another Hugging Face Example

You'll often see:

class GemmaForCausalLM(PreTrainedModel):

    def __init__(self, config):

        super().__init__(config)

Again:

The parent class performs common setup.

The child then adds Gemma-specific layers.

A Common Misconception

Some people think:

"super() means 'go to the top-most parent.'"

Not exactly.

For now, the useful mental model is:

super() gives you access to the parent class's implementation.

Later, if we study multiple inheritance, we'll refine this because Python's method resolution is more sophisticated. For the ML frameworks you'll use, this simpler model is accurate enough.

Engineer's Thinking

Whenever you see:

super().__init__()

Don't treat it as boilerplate.

Ask yourself:

What initialization is happening in the parent?
Why is it important?
What capabilities is the parent setting up?

That's how you begin to understand framework internals.

Notes (Reference)
Topic: Method Overriding & super()
Why does this exist?

To let a child class customize behavior inherited from its parent while still reusing the parent's common functionality.

Mental Model
Parent
   │
Common Behavior
   │
   ▼
Child
Reuses most behavior
Overrides only what is different

super() means:

"Use the parent's implementation before (or while) adding my own."

Key Ideas
A child can replace a parent's method by defining a method with the same name.
This is called method overriding.
Overriding lets classes specialize behavior.
super() calls the parent class's implementation.
super() avoids duplicating common logic.
Syntax
class Parent:
    def greet(self):
        ...

class Child(Parent):
    def greet(self):
        super().greet()
        ...
Where will I see this?

PyTorch:

class MyModel(nn.Module):

    def __init__(self):
        super().__init__()

    def forward(self, x):
        ...

Hugging Face:

class GemmaForCausalLM(PreTrainedModel):

    def __init__(self, config):
        super().__init__(config)
Common Mistakes
Forgetting to call super().__init__() when inheriting from framework base classes.
Thinking overriding removes inheritance—it doesn't.
Rewriting parent logic instead of reusing it through super().
Takeaway

Inheritance lets you reuse common behavior.

Method overriding lets you customize specific behavior.

super() lets you reuse the parent's implementation instead of duplicating it.

Together, these three ideas explain a huge amount of how PyTorch and Hugging Face are structured.
