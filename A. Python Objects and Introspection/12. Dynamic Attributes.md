Topic: Dynamic Attributes
Why does this exist?

To allow objects to gain or modify attributes while the program is running, making them flexible enough to represent different kinds of data.

Mental Model

An object is like a backpack.

You can add new items (attributes) as needed.

Key Ideas
Python objects can have attributes added dynamically.
Dot notation is the most common way to access attributes.
getattr() accesses an attribute by name.
setattr() creates or updates an attribute by name.
hasattr() checks whether an attribute exists.
Syntax
person.name = "Alice"

getattr(person, "name")

setattr(person, "city", "Bengaluru")

hasattr(person, "salary")
Where will I see this?
Hugging Face configuration objects.
Model output objects.
SDK response objects.
Generic utility functions.
Debugging unfamiliar libraries.
Common Mistakes
Assuming every object has every attribute.
Forgetting to check for optional attributes in generic code.
Overusing dynamic attributes in your own designs when a fixed structure would be clearer.
Takeaway

Dynamic attributes let Python objects be flexible without requiring a new class for every variation. This flexibility is one reason Python libraries can build expressive APIs while still letting you inspect and explore objects naturally.
