Topic: Decorators
Why do they exist?

To add or modify behavior around a function or method without changing its core implementation.

Mental Model

A decorator wraps a function, like wrapping a gift.

The gift stays the same.

The wrapper adds extra behavior.

Key Ideas
@ applies a decorator.
Decorators add behavior around functions or methods.
Different decorators serve different purposes.
Focus on understanding what a decorator does, not just its syntax.
Common Decorators
Decorator	Purpose
@property	Makes a method behave like an attribute
@classmethod	Method belongs to the class, often used for alternative constructors
@staticmethod	Utility method that doesn't need an instance or the class
@torch.no_grad()	Runs code without gradient tracking

Common Mistakes
Thinking @ is magic—it simply applies a decorator.
Trying to memorize every decorator instead of understanding its purpose.
Assuming every decorator changes a function's logic; many only change how it's called or the environment in which it runs.
Takeaway

Decorators are a way to attach reusable behavior to functions and methods. When reading ML frameworks, focus on what behavior the decorator adds, because that's what matters when understanding the code.

Let's connect this to your work

Imagine you're reading your team's SDK and you see:

@register_backend
class SnapdragonBackend:
    ...

Even if you've never seen @register_backend before, you now know how to think:

It's a decorator.
It's adding some behavior.
The likely purpose is to register this backend with a registry so the SDK can discover and use it automatically.

You don't need to know the implementation immediately. You already understand the pattern.
