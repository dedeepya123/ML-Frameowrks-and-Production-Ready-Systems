Goal

By the end of this lesson, you should be able to answer:

What is a variable?
What is an object?
What is a reference?
Where is the actual data?
Why do assignments sometimes affect other variables?
Let's start with a simple question

Consider:

x = 10
Question

Where is 10?

Most beginners answer:

"Inside x."

This is not the best mental model.

What actually happens?

Think of Python in three steps.

Step 1 — Python creates an object
10

Python creates an Integer Object somewhere in memory.

Memory

┌───────────────┐
│ Integer Object│
│ value = 10    │
└───────────────┘
Step 2 — Python creates a name
x

x is not the integer.

It is simply a name.

Step 3 — The name points to the object
x
│
▼
┌───────────────┐
│ Integer Object│
│ value = 10    │
└───────────────┘

This arrow is called a reference.

What is a reference?

A reference is simply:

A way for one object (or a variable name) to point to another object.

Think of it like a contact in your phone.

Mom

The contact isn't your mother.

It points to information about your mother.

Similarly,

x

isn't the integer.

It points to the integer object.

Now let's make it interesting
x = 10
y = x

What happens?

Many people imagine:

x → 10

y → 10

That picture is incomplete.

The real picture is:

          ┌─────────────┐
          │ Integer(10) │
          └─────────────┘
             ▲       ▲
             │       │
             │       │
             x       y

There is one object.

Two names refer to it.

Does this always happen?

Let's use a list.

numbers = [1, 2, 3]

other = numbers

Picture:

            ┌─────────────────┐
            │ List Object     │
            │ [1,2,3]         │
            └─────────────────┘
               ▲          ▲
               │          │
         numbers       other

Still one object.

Two references.

Now something surprising
other.append(4)

What do you expect?

Many beginners think:

numbers

[1,2,3]

other

[1,2,3,4]

But that's impossible.

Why?

Because there aren't two lists.

There is only one list.

So after appending:

            ┌─────────────────┐
            │ List Object     │
            │ [1,2,3,4]       │
            └─────────────────┘
               ▲          ▲
               │          │
         numbers       other

Both names see the change.

Why is this important?

Imagine this at work.

model = load_model()

another = model

You now have:

model ───────┐
             │
             ▼
        Model Object
             ▲
             │
another ─────┘

If you call:

model.eval()

Did you create a new model?

No.

You changed the existing model object.

So:

another.training

also reflects that change.

Understanding references helps explain this behavior.

Reassignment is different

Now look at:

x = 10

x = 20

Many people think:

10 becomes 20

That's not what happens.

Instead:

Step 1

x
│
▼
10

Step 2

Python creates another object.

20

Step 3

The reference changes.

Before

x
│
▼
10

After

10

x
│
▼
20

The original object wasn't modified.

The name now points somewhere else.

Mutable vs Immutable (Just an intuition)

We'll study this in depth later, but you need a preview.

Some objects can change.

Examples:

list
dictionary
set

Some objects cannot.

Examples:

int
float
string
tuple

This is why:

numbers.append(4)

changes the existing list.

But:

x = x + 1

doesn't modify the integer object.

It creates a new integer object and rebinds x to it.

Connecting this to Hugging Face

Suppose you write:

model = AutoModelForCausalLM.from_pretrained(...)

backup = model

You do not have two models.

You have:

model ──────┐
            │
            ▼
      Model Object
            ▲
            │
backup ─────┘

If someone modifies that object, both names refer to the updated state.

This mental model becomes especially important when reading production code and debugging.

Mental Model

Imagine objects as houses.

Variables are addresses written in your notebook.

Notebook

Home

↓

Actual House

If you write the same address twice:

Home

Vacation Home

both entries point to the same house.

You didn't build another house.

Notes
Topic: Variables, Objects & References
What is a Variable?

A variable is a name that refers to an object.

What is an Object?

The actual entity stored in memory.

What is a Reference?

A link from a variable to an object.

Key Ideas
Variables are not objects.
Variables point to objects.
Multiple variables can point to the same object.
Reassignment changes the reference, not necessarily the object.
Mutable objects can change in place; immutable objects cannot.
Mental Model

Variables are labels attached to objects, not containers holding values.

Why does this matter?

ML frameworks often pass around references to large objects like models and tensors. Understanding references helps you reason about shared state, side effects, and debugging without confusion.
