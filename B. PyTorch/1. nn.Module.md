Topic: nn.Module
Why does it exist?

To provide the common infrastructure that every PyTorch model needs, so individual models only implement their unique architecture.

Mental Model

nn.Module is the foundation of a building.

Every model is built on top of it.

The foundation provides shared functionality.

The model adds the architecture.

Key Ideas
Every PyTorch model inherits from nn.Module.
nn.Module manages parameters, submodules, and buffers.
It enables device management (to(), cpu(), cuda()).
It supports training/evaluation modes.
It provides saving and loading through state_dict().
Common Capabilities
Capability	Example
Parameters	model.parameters()
Submodules	model.named_modules()
Devices	model.to("cuda")
Modes	model.train(), model.eval()
Saving	model.state_dict()
Where will I see this?
Every custom model you write.
Every Hugging Face model.
Every PyTorch layer (nn.Linear, nn.Conv2d, nn.LayerNorm, etc.) because they all inherit from nn.Module.
Common Mistakes
Thinking nn.Module performs the neural network computation—it mainly provides the infrastructure.
Forgetting that model(x) calls __call__(), which then invokes forward().
Assuming methods like parameters() are implemented separately in every model—they're inherited.
Takeaway

nn.Module is the backbone of the PyTorch model system. It gives every model a consistent set of capabilities, while letting each model focus only on defining its own computation.
