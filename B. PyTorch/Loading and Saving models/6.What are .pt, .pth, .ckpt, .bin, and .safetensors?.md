Lesson 6 – What are .pt, .pth, .ckpt, .bin, and .safetensors?
Step 1 — Start with a question

Suppose I write:

torch.save(model.state_dict(), "model.pt")

Now I change only the filename:

torch.save(model.state_dict(), "model.xyz")

Question:

Will PyTorch fail?

No.

It still works.

Why?

Because:

PyTorch doesn't care about the extension.

This is the first important realization.

Step 2 — Then why do extensions exist?

Extensions are mainly for humans and tools.

Think about:

photo.jpg

photo.png

report.pdf

movie.mp4

The extension tells people:

"This file probably contains this kind of data."

Similarly,

model.pt

tells engineers:

"This is probably a PyTorch-related file."

The extension itself doesn't define the contents.

Step 3 — What is inside a .pt file?

Suppose we save:

torch.save(model.state_dict(), "model.pt")

Internally:

OrderedDict

↓

Serialized bytes

↓

model.pt

The .pt file does not know it's a model.

It simply contains the serialized Python object.

Suppose instead:

torch.save(
    {
        "epoch": 10,
        "loss": 0.25
    },
    "training.pt"
)

Now the .pt file contains:

Dictionary

↓

Serialized bytes

Same extension.

Completely different contents.

Step 4 — So what is .pt?

It is simply a convention.

People usually use:

.pt

for PyTorch-related serialized objects.

That's all.

Step 5 — Then what is .pth?

Exactly the same idea.

Historically you'll see:

weights.pth

checkpoint.pth

model.pth

There is no fundamental difference between:

.pt

.pth

Both are conventions.

Many projects use them interchangeably.

Step 6 — Then what is .ckpt?

Now things become interesting.

.ckpt usually means:

Checkpoint

Notice:

Checkpoint is not a file format.

It is a kind of information.

Usually:

Checkpoint

↓

Dictionary

↓

{
    model_state,
    optimizer_state,
    epoch,
    scheduler_state,
    ...
}

This dictionary might be saved using:

torch.save(...)

Someone simply names it:

checkpoint.ckpt

The extension tells you:

"This is probably a training checkpoint."

Step 7 — Then what is .bin?

You'll often see:

pytorch_model.bin

Especially in older Hugging Face repositories.

Again,

.bin

just means:

Binary file.

Historically Hugging Face stored serialized model weights in .bin files using PyTorch serialization.

So:

pytorch_model.bin

usually contained something equivalent to a model state dictionary.

Again:

The extension isn't what matters.

The serialization method matters.

Step 8 — Then what is .safetensors?

This one is different.

Unlike:

.pt

.pth

.bin

which are mostly naming conventions around PyTorch serialization,

SafeTensors is an actual file format.

Its goals are:

Fast loading.
Safe loading.
Predictable layout.
Avoid executing arbitrary Python code during loading.

Think of it as an alternative container specifically designed for tensors.

Instead of relying on Python object serialization, it stores tensor metadata and raw tensor bytes in a structured format.

That's why it's become the preferred format for distributing many modern models.

Step 9 — Why was SafeTensors created?

Traditional PyTorch serialization can reconstruct arbitrary Python objects.

That flexibility is powerful, but it also means you should only load files from sources you trust.

SafeTensors intentionally supports a much narrower use case:

Tensor storage

and avoids arbitrary object reconstruction.

That's why it's considered safer for sharing pretrained model weights.

Step 10 — Mental Picture
Traditional PyTorch
Python Object

↓

torch.save()

↓

Serialized File (.pt/.pth/.bin)

Can represent many different Python objects.

SafeTensors
Tensor Data

↓

SafeTensors Format

↓

.safetensors

Designed specifically for tensors and their metadata.

Comparison
Extension	What it really means	Typical contents
.pt	PyTorch convention	Tensor, state_dict, checkpoint, or other serialized object
.pth	PyTorch convention	Same as .pt
.ckpt	Naming convention for a checkpoint	Usually model state + optimizer state + metadata
.bin	Generic binary filename (older HF often used it)	Often model weights
.safetensors	Dedicated tensor storage format	Tensor weights and metadata

Notice that only SafeTensors represents a distinct storage format.

Where you'll encounter them
During research

Often:

model.pt

weights.pth
During training

Often:

checkpoint.pt

checkpoint.ckpt
Hugging Face

Historically:

pytorch_model.bin

Today, many repositories provide:

model.safetensors
Engineer's Thinking

When you download:

gemma-2b.safetensors

You shouldn't think:

"This is a different model."

Instead think:

"Same model, different storage format."

Similarly,

checkpoint.ckpt

doesn't mean:

"Special checkpoint format."

It usually means:

"Someone chose this filename because it stores training checkpoint information."

Notes (Reference)
File extension ≠ file format

Most extensions (.pt, .pth, .ckpt, .bin) are conventions that help humans understand what the file is likely to contain.

SafeTensors
A dedicated format for storing tensors.
Optimized for safe and efficient loading.
Common for distributing pretrained models.
Typical usage
.pt / .pth → General PyTorch serialization.
.ckpt → Training checkpoints.
.bin → Older Hugging Face weight files.
.safetensors → Modern pretrained model weights.
