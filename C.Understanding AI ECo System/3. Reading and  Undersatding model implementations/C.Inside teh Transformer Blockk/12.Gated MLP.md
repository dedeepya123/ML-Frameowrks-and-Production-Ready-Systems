# Module 5 — Feed-Forward Network / MLP

## Lesson 2 — Gated MLP / SwiGLU

## 1. Purpose of the MLP

Attention and MLP have different responsibilities.

Attention:

    mixes information across sequence positions

MLP:

    performs nonlinear transformation independently at each token position

Therefore:

    Attention → token ↔ token interaction

    MLP → token-wise transformation

---

## 2. Ordinary FFN

The basic FFN is:

    x
    ↓
    W1
    ↓
    activation
    ↓
    W2
    ↓
    output

Mathematically:

    FFN(x) = W2(activation(W1x))

If:

    x = [B,S,H]

then typically:

    [B,S,H]
        ↓
    [B,S,I]
        ↓
    [B,S,I]
        ↓
    [B,S,H]

where:

    H = hidden_size
    I = intermediate_size

---

## 3. Gated MLP

Modern LLMs commonly use a gated MLP.

Instead of one intermediate branch, the input produces two branches:

    x
    ├── gate_proj
    └── up_proj

The gate branch is activated:

    activation(gate_proj(x))

Then it is multiplied elementwise with the up branch:

    activation(gate_proj(x)) * up_proj(x)

Finally:

    down_proj(...)

So:

    x
    ├──→ gate_proj → activation ──┐
    │                             ×
    └──→ up_proj ─────────────────┘
                                  ↓
                              down_proj
                                  ↓
                               output

---

## 4. SwiGLU

When the activation is SiLU:

    SiLU(x) = x * sigmoid(x)

the gated structure is commonly referred to as SwiGLU.

The computation is:

    hidden =
        SiLU(gate_proj(x))
        * up_proj(x)

    output =
        down_proj(hidden)

The exact implementation should always be verified from the model code rather than inferred only from class names.

---

## 5. Why three projections?

The three projections have different roles.

### gate_proj

Creates the gate branch:

    x → intermediate representation

### up_proj

Creates the feature/information branch:

    x → intermediate representation

### down_proj

Projects the combined intermediate representation back:

    intermediate_size → hidden_size

Therefore:

    gate_proj
    up_proj
        ↓
    elementwise multiplication
        ↓
    down_proj

Three projections are required because the architecture has two incoming branches and one outgoing projection.

---

## 6. Shape reasoning

Suppose:

    x = [B,S,H]

and:

    intermediate_size = I

Then:

    gate_proj(x) → [B,S,I]

    up_proj(x) → [B,S,I]

    activation(gate) → [B,S,I]

    activation(gate) * up
        → [B,S,I]

    down_proj(...)
        → [B,S,H]

The sequence dimension S is never mixed.

There is no [S,S] operation inside the MLP.

---

## 7. Why is it called "gated"?

The gate branch modulates the feature branch.

Example:

    gate = [0.1, 0.9, 0.2]

    up = [10, 10, 10]

    gate * up
      = [1, 9, 2]

The multiplication is elementwise.

The gate is therefore per intermediate feature, not one scalar for the entire token.

---

## 8. Attention vs MLP

Attention:

    QKᵀ
       ↓
    [S,S]
       ↓
    token-to-token interaction

MLP:

    [B,S,H]
       ↓
    [B,S,I]
       ↓
    [B,S,H]

No token-to-token interaction occurs.

A useful mental model:

    Attention = communication

    MLP = computation/transformation

---

## 9. Recognizing a gated MLP in unfamiliar code

Look for a pattern like:

    gate = gate_proj(x)
    up = up_proj(x)

    hidden = activation(gate) * up

    output = down_proj(hidden)

Or:

    self.act_fn(self.w1(x)) * self.w3(x)

followed by:

    self.w2(...)

Names can change:

    gate_proj / up_proj / down_proj

    w1 / w3 / w2

    gate / up / down

The data flow is what matters.

---

## 10. Code-reading strategy

When inspecting a new model's MLP:

1. Find the MLP class.
2. Inspect `__init__`.
3. Identify the projection layers.
4. Check their input/output dimensions.
5. Inspect `forward()`.
6. Find the activation.
7. Find whether two branches are multiplied.
8. Find the final projection back to hidden_size.
9. Draw the data flow yourself.
10. Verify every tensor shape.

Do not memorize layer names.

Reason from:

    operations + shapes + data flow

---

## 11. Transformer layer mental model

A decoder Transformer layer contains two major computational blocks:

    x
    ↓
    normalization
    ↓
    Attention
    ↓
    residual
    ↓
    normalization
    ↓
    Gated MLP
    ↓
    residual
    ↓
    next layer

Attention:

    gathers information from other tokens.

MLP:

    transforms the resulting token representation.

---

## 12. Systems perspective

Architectural requirement:

    gate_proj(x)
    up_proj(x)

Implementation does not necessarily have to execute these as two completely independent operations.

Because both consume the same x, an implementation may combine/fuse their computation:

    combined_projection(x)
             ↓
        ┌────┴────┐
       gate       up

This illustrates an important distinction:

    Architecture
        =
    what computation must happen

    Implementation
        =
    how that computation is executed efficiently
