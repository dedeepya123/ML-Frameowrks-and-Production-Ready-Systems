# Module 5 — Feed-Forward Network / MLP

## Lesson 3 — Normalization

## 1. Purpose

Normalization controls the scale/statistics of hidden representations so that the transformations inside a deep Transformer can be trained and executed more stably.

It does not change the hidden-state shape.

For:

    x = [B,S,H]

normalization is generally performed over the hidden dimension H independently for each token.

Therefore:

    [B,S,H] → [B,S,H]

---

## 2. Which dimension is normalized?

Given:

    x.shape = [B,S,H]

normalization usually uses:

    dim = -1

meaning:

    hidden dimension H

Each token is normalized independently.

There is no token-to-token interaction.

---

## 3. LayerNorm

For one token vector x:

    μ = mean(x)

    σ² = mean((x - μ)²)

    x̂ = (x - μ) / sqrt(σ² + ε)

Then:

    y = γx̂ + β

LayerNorm therefore:

    x
    ↓
    subtract mean
    ↓
    divide by standard deviation
    ↓
    learned scale γ
    ↓
    learned bias β
    ↓
    output

Typical learnable parameters:

    weight / gamma
    bias / beta

---

## 4. RMSNorm

Modern LLMs commonly use RMSNorm.

RMS:

    RMS(x) =
        sqrt(mean(x²) + ε)

Normalization:

    x̂ = x / RMS(x)

Then:

    y = γx̂

RMSNorm therefore:

    x
    ↓
    square
    ↓
    mean
    ↓
    sqrt
    ↓
    divide x by RMS
    ↓
    multiply learned weight
    ↓
    output

Important difference:

RMSNorm does NOT explicitly subtract the mean.

It also typically has no learned bias.

---

## 5. LayerNorm vs RMSNorm

LayerNorm:

    - computes mean
    - computes variance
    - subtracts mean
    - divides by standard deviation
    - learned scale
    - usually learned bias

RMSNorm:

    - does not subtract mean
    - computes root mean square
    - divides by RMS
    - learned scale
    - typically no bias

---

## 6. Why epsilon?

Normalization contains division by a quantity derived from variance/RMS.

If that quantity becomes extremely small, division can become numerically unstable.

Therefore:

    variance + epsilon

or:

    mean(x²) + epsilon

is used.

Common values may be:

    1e-5
    1e-6

The exact value is architecture/implementation dependent.

---

## 7. `rsqrt`

Optimized code may use:

    torch.rsqrt(x)

instead of:

    1 / torch.sqrt(x)

because:

    rsqrt(x) = 1 / sqrt(x)

Therefore:

    x / sqrt(a)

can be implemented as:

    x * rsqrt(a)

Same mathematical operation.

---

## 8. Why normalize before Attention/MLP?

In pre-normalization architectures:

    x
    ↓
    Norm
    ↓
    Attention
    ↓
    residual add
    ↓
    Norm
    ↓
    MLP
    ↓
    residual add

Normalization gives the sublayer a controlled input representation.

This is called pre-norm.

Exact normalization placement is an architectural choice and should be verified from the model implementation.

---

## 9. Residual stream

The hidden representation flowing through Transformer layers can be thought of as the residual stream.

Conceptually:

    residual stream
          │
          ├──→ Norm → Attention ──┐
          │                       │
          └────────────── + ──────┘
                          │
                    updated stream
                          │
                          ├──→ Norm → MLP ──┐
                          │                 │
                          └────── + ────────┘
                                    │
                                    ↓
                              next layer

Attention and MLP read the residual stream and write updates back into it.

Normalization prepares the representation before each transformation.

---

## 10. Recognizing normalization from code

RMSNorm-like code may contain:

    x.pow(2)
    mean(dim=-1)
    rsqrt(...)
    x * weight

Reason:

    square → mean → reciprocal sqrt → scale

This indicates RMS normalization.

LayerNorm-like code may contain:

    mean
    variance
    x - mean
    sqrt(variance + eps)
    weight
    bias

Reason:

    center → normalize by variance → scale → shift

---

## 11. Shape reasoning

For:

    x = [B,S,H]

RMS calculation:

    mean(x², dim=-1, keepdim=True)

produces:

    [B,S,1]

Then:

    x / RMS

uses broadcasting:

    [B,S,H]
        /
    [B,S,1]

    →
    [B,S,H]

The learned weight has shape:

    [H]

and broadcasts over B and S.

Final shape remains:

    [B,S,H]

---

## 12. Compare the three major Transformer operations

Attention:

    [B,H,S,D]
        ↓
    QKᵀ
        ↓
    [B,H,S,S]

    Purpose:
    token-to-token information mixing.

MLP:

    [B,S,H]
        ↓
    [B,S,I]
        ↓
    [B,S,H]

    Purpose:
    token-wise nonlinear transformation.

Normalization:

    [B,S,H]
        ↓
    [B,S,H]

    Purpose:
    normalize hidden features within each token.

---

## 13. Code-reading rule

Never depend only on the class name.

Instead identify:

    Which dimension is reduced?

    Is the mean subtracted?

    Is variance calculated?

    Is mean-square calculated?

    Is there rsqrt?

    Is there a learned weight?

    Is there a learned bias?

From these operations you can identify the normalization mechanism.

---

## 14. Gemma/code-reading mental model

When seeing something like:

    x * rsqrt(mean(x²) + eps) * weight

translate it as:

    RMS normalization over hidden features

Then map it to the architecture:

    hidden_states
        ↓
    RMSNorm
        ↓
    Attention / MLP
        ↓
    residual stream

The class name is secondary.

Operations + shapes + data flow are primary.
