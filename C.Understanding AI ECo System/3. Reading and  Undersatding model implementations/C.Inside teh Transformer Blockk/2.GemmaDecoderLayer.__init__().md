# Module 4 — Inside the Transformer Block

## Lesson 2 — GemmaDecoderLayer.__init__()

### Purpose

The constructor of GemmaDecoderLayer creates the components required to implement one Transformer decoder block.

### Main components

GemmaDecoderLayer
├── input_layernorm
├── self_attn
├── post_attention_layernorm
└── mlp

### 1. input_layernorm

Type:
GemmaRMSNorm

Purpose:
Normalize the incoming hidden representation before self-attention.

Input:
[batch, sequence_length, hidden_size]

Output:
Same shape.

Concept:
Pre-normalization.

---

### 2. self_attn

Type:
GemmaAttention

Purpose:
Perform multi-head self-attention.

Conceptual components:

self_attn
├── q_proj
├── k_proj
├── v_proj
├── rotary_emb
└── o_proj

The decoder layer delegates the detailed attention implementation to GemmaAttention.

Multi-head intuition:

hidden_states
    [B, S, H]
       ↓
Q/K/V projections
       ↓
[B, heads, S, head_dim]

Example:

H = 3072
heads = 24
head_dim = 128

24 × 128 = 3072

The multiple heads allow attention to operate in multiple learned representation subspaces.

---

### 3. post_attention_layernorm

Type:
GemmaRMSNorm

Purpose:
Normalize the representation after the attention/residual stage and before the MLP.

---

### 4. mlp

Type:
GemmaMLP

Purpose:
Perform the feed-forward/nonlinear transformation inside the Transformer block.

Conceptually uses a gated MLP:

hidden_states
    ├── gate_proj → activation
    └── up_proj
              ↓
        element-wise multiplication
              ↓
          down_proj

The detailed implementation will be studied in a later lesson.

---

## Important software-design insight

GemmaDecoderLayer does not directly implement all attention and MLP operations.

Instead it composes specialized modules:

GemmaDecoderLayer
    ├── GemmaAttention
    ├── GemmaMLP
    └── GemmaRMSNorm

Each class owns one level of responsibility.

---

## Code-reading principle

When reading an unfamiliar model:

1. Inspect __init__().
2. Identify child modules.
3. Map each child module to an architectural concept.
4. Then inspect forward() to determine execution order and tensor flow.

The constructor gives the architecture/object hierarchy.

The forward() gives the computation/execution flow.
