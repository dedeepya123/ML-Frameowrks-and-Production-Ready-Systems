# Module 4 — Inside the Transformer Block

## Lesson 9 — Causal Attention Mask

## 1. Why causal masking is needed

Self-attention naturally allows every query position to attend to every key position.

For a causal language model, this is not allowed.

A token must not access future tokens.

For sequence positions 0,1,2,3:

Query 0 → Key 0
Query 1 → Key 0,1
Query 2 → Key 0,1,2
Query 3 → Key 0,1,2,3

---

## 2. Causal attention pattern

For sequence length 4:

    K0 K1 K2 K3

Q0  ✓  ✗  ✗  ✗
Q1  ✓  ✓  ✗  ✗
Q2  ✓  ✓  ✓  ✗
Q3  ✓  ✓  ✓  ✓

This is a lower-triangular pattern.

The diagonal is allowed because a token may attend to itself.

---

## 3. Where masking happens

Attention flow:

Q/K/V projections
    ↓
split into heads
    ↓
RoPE(Q,K)
    ↓
QKᵀ
    ↓
scale by sqrt(head_dim)
    ↓
CAUSAL MASK
    ↓
softmax
    ↓
attention weights × V

The mask is applied to attention scores, not directly to Q, K, or V.

---

## 4. How masking works

Forbidden attention scores are effectively assigned -∞.

Example:

Before:

[2.1, 4.2, 1.7]

After causal masking for position 0:

[2.1, -∞, -∞]

Then softmax:

[1, 0, 0]

because:

exp(-∞) = 0

Therefore future positions receive zero attention probability.

---

## 5. Why masking happens before softmax

Correct:

QKᵀ
 ↓
mask
 ↓
softmax

The forbidden positions become zero probability naturally.

If masking happened after softmax, the remaining probabilities would need additional renormalization.

---

## 6. Training

During training, the whole sequence can be processed in parallel.

Example:

[The, cat, sat, on, mat]

produces a full 5 × 5 attention-score matrix.

The causal mask prevents each position from accessing future positions.

Therefore:

parallel matrix computation + causal mask
=
autoregressive behavior

---

## 7. Inference

During autoregressive generation, tokens are generated one at a time.

With KV caching, a new token at position 100 has:

current query:
Q100

cached keys:
K0 ... K100

It can attend to all of them.

Future keys do not exist yet.

Therefore optimized single-token decoding may not require the same explicit full triangular mask used during training.

---

## 8. Multi-head attention

If:

B = batch size
H = number of heads
S = sequence length
D = head dimension

Then:

Q/K/V:
[B, H, S, D]

Attention scores:

QKᵀ:
[B, H, S, S]

Each head has its own attention scores.

The causal restriction is generally the same across heads:

✓ ✗ ✗
✓ ✓ ✗
✓ ✓ ✓

The actual scores differ because every head has different Q/K representations.

---

## 9. Broadcasting

A causal mask may conceptually have shape:

[S, S]

while attention scores have:

[B, H, S, S]

The mask can be broadcast across batch and head dimensions.

This avoids unnecessarily storing identical copies for every batch/head.

---

## 10. Causal mask vs RoPE

These are different concepts.

### RoPE

Answers:

"Where is this token?"

It injects positional information into Q/K.

### Causal mask

Answers:

"Which positions is this token allowed to attend to?"

It prevents future information from flowing backward.

Therefore:

RoPE = positional information

Causal mask = information-flow restriction

---

## 11. Causal mask vs padding mask

Causal mask:
prevents attending to future positions.

Padding mask:
prevents attending to padding tokens.

They solve different problems and may sometimes be combined into an attention mask.

---

## 12. Code-reading mental model

When seeing:

attn_weights = Q @ Kᵀ

think:
"Calculate query-key similarity."

When seeing:

attn_weights = attn_weights / sqrt(head_dim)

think:
"Scale attention logits."

When seeing:

attn_weights += causal_mask

think:
"Prevent future-token information flow."

When seeing:

softmax(attn_weights, dim=-1)

think:
"Convert valid key scores into attention probabilities."

---

## 13. One-sentence summary

Causal masking is applied to the attention scores before softmax so that each token can attend only to itself and earlier tokens, preventing future-token information from influencing its prediction.

``` text
                 hidden_states
                      │
              ┌───────┼───────┐
              ↓       ↓       ↓
           q_proj   k_proj   v_proj
              ↓       ↓       ↓
              Q       K       V
              │       │
              ↓       ↓
           split into heads
              │       │
              ↓       ↓
             RoPE   RoPE
              │       │
              ↓       ↓
             Q'      K'
              │       │
              └───┬───┘
                  ↓
                Q'K'ᵀ
                  ↓
              / √D
                  ↓
             causal mask
                  ↓
               softmax
                  ↓
          attention weights
                  │
                  ×
                  V
                  ↓
          per-head outputs
                  ↓
          combine heads
                  ↓
                o_proj
```

During autoregressive single-token decoding with KV caching, an explicit causal mask is generally unnecessary because the query only attends to keys that already exist. During prompt prefill, causal masking is still required unless the attention implementation/kernel enforces causality implicitly.
