# Module 3 – Lesson 1

# Why Multiple Model Classes?

## Problem

Should one class implement every possible task?

No.

Different tasks require different outputs and behaviors.

---

## Design

Separate responsibilities.

Base Model:
- Embeddings
- Transformer layers
- Final normalization
- Produces hidden states

Task Model:
- Reuses the base model
- Adds a task-specific head
- Produces task-specific outputs

---

## Benefits

- Single Responsibility
- Code Reuse
- Easier Maintenance
- Easier Extension
- Lower Memory Usage
- Clearer Architecture

---

## Design Principles

- Single Responsibility Principle
- Composition
- Open/Closed Principle
- Factory Pattern

---

## Key Takeaways

- The Transformer and task heads have different responsibilities.
- Task-specific models reuse the base model instead of duplicating it.
- New tasks can be added by creating new wrapper classes around the base model.


**Why doesn't Hugging Face put everything into one class?**

I'd want you to answer:

Different tasks require different outputs and behaviors. By separating the reusable Transformer (GemmaModel) from task-specific heads (GemmaForCausalLM, classification models, etc.), Hugging Face keeps each class focused, avoids duplication, improves maintainability, and makes it easy to extend the architecture for new tasks.
