# Class: GemmaModel

## 1. Purpose

Implement the core Gemma decoder-only Transformer architecture.

It transforms token IDs into contextual hidden representations.

---

## 2. Responsibility

Responsible for:

- Token embedding
- Running the stack of decoder layers
- Final normalization
- Producing hidden states

Not responsible for:

- Language-modeling logits
- Token sampling
- Task-specific heads
- Classification

---

## 4. State (__init__)

### embed_tokens

Embedding module.

Purpose:

Token IDs → embedding vectors.

### layers

ModuleList containing multiple GemmaDecoderLayer objects.

Purpose:

Represent the repeated Transformer blocks.

### norm

Final Gemma RMSNorm.

Purpose:

Normalize the final hidden representation.

## 8. Deep Learning Concept

Represents the decoder-only Transformer body.

Theory → Code:

Token embedding → embed_tokens

Transformer blocks → GemmaDecoderLayer

Repeated blocks → ModuleList

Final normalization → norm

Contextual representation → hidden_states

---

## 9. Engineering Decisions

### Why separate GemmaDecoderLayer?

Each class owns one level of responsibility.

GemmaModel:
- orchestrates the stack.

GemmaDecoderLayer:
- implements one Transformer block.

### Why ModuleList?

Allows a variable number of decoder layers while registering them as PyTorch submodules.

### Why separate embedding and norm?

They are independent architectural components with their own parameters/behavior.

---

## 10. Simplified Implementation

class GemmaModel(GemmaPreTrainedModel):

    def __init__(self, config):
        super().__init__(config)

        self.embed_tokens = nn.Embedding(...)
        self.layers = nn.ModuleList([...])
        self.norm = GemmaRMSNorm(...)

    def forward(self, input_ids):
        hidden_states = self.embed_tokens(input_ids)

        for layer in self.layers:
            hidden_states = layer(hidden_states)

        hidden_states = self.norm(hidden_states)

        return hidden_states

---

## 11. Key Takeaways

- GemmaModel is the core Transformer body.
- It converts token IDs into contextual hidden states.
- It is primarily an orchestrator of child modules.
- Its constructor reveals the model's object hierarchy.
- Its forward method reveals the computational flow.
- Reading __init__ + forward gives a high-level understanding of the architecture.
- It does not itself implement attention, MLP, or normalization mathematics; it delegates those responsibilities to child modules.
