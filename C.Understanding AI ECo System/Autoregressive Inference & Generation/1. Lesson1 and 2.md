# Module 9 — Autoregressive Inference & Generation

## Lesson 1 — What Happens When an LLM Generates Text?

An LLM generates text by repeatedly performing next-token prediction:

```text
current tokens
     ↓
Transformer
     ↓
logits
     ↓
choose next token
     ↓
append token
     ↓
repeat
```

`generate()` is built around this fundamental loop.

The Transformer produces logits; the generation strategy decides which token to select.

Important distinction:

```text
Transformer → computes next-token distribution
Generation  → chooses the actual next token
```

## Lesson 2 — Why Is Generation Autoregressive?

Autoregressive generation means:

> Each new token is predicted using the tokens generated before it, and the newly generated token becomes part of the context for the next prediction.

Conceptually:

```text
x₁
 ↓
x₁ x₂
 ↓
x₁ x₂ x₃
 ↓
x₁ x₂ x₃ x₄
```

The probability of a sequence is decomposed into conditional next-token probabilities:

```text
P(x₁, x₂, ..., xₙ)
=
P(x₁)
× P(x₂ | x₁)
× P(x₃ | x₁,x₂)
× ...
```

### Training vs Inference

**Training:**

The complete target sequence is known, so Transformer computations can be parallelized across positions while the causal mask prevents each position from seeing future tokens.

```text
The cat sat on the mat
 ↓
parallel predictions
```

**Inference:**

Future tokens are unknown, so they must be generated sequentially.

```text
prompt
 ↓
predict token
 ↓
append token
 ↓
predict next token
 ↓
repeat
```

Therefore:

> Training is parallel across sequence positions, while autoregressive decoding is sequential across generated tokens.

### Key consequence

Repeated decoding raises a major efficiency question:

> Are we recomputing information that was already calculated for previous tokens?

This leads directly to the KV-cache problem.

### Mental model

```text
Autoregressive dependency
        ↓
sequential decoding
        ↓
repeated model execution
        ↓
recomputation
        ↓
KV Cache
```
