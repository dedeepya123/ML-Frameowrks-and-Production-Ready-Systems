# Module 9 — Autoregressive Inference & Generation

## Lesson 12 — `generate()` as Orchestration

### 1. What is `generate()`?

`generate()` is the orchestration/control layer for autoregressive generation.

It repeatedly:

```text
prepare input
↓
call model.forward()
↓
receive logits
↓
select next token
↓
update generation state
↓
check stopping
↓
repeat
```

---

### 2. Model vs Generation

The model answers:

> Given these inputs, what are the logits?

Generation answers:

> What should I do with those logits, and should I continue?

Therefore:

```text
generate()
    ↓
forward()
    ↓
Transformer computation
```

---

### 3. First step — Prefill

Prompt:

```text
[A B C]
```

First model call:

```text
[A B C]
    ↓
Transformer
    ↓
logits + KV cache
```

The KV cache now contains the prompt's K/V state.

---

### 4. Decode steps

Next token:

```text
[D]
```

is passed together with the existing cache.

Conceptually:

```text
[D] + cache(A,B,C)
       ↓
model
       ↓
logits + updated cache
```

Then:

```text
[E] + cache(A,B,C,D)
```

and so on.

---

### 5. Simplified generation loop

```python
input_ids = prompt
past_key_values = None

while not finished:

    outputs = model(
        input_ids=input_ids,
        past_key_values=past_key_values,
        use_cache=True,
    )

    logits = outputs.logits

    next_token = select_next_token(logits)

    past_key_values = outputs.past_key_values

    input_ids = next_token

    if stopping_condition:
        break
```

This is conceptual pseudocode, not the complete Hugging Face implementation.

---

### 6. Generation is stateful

Generation maintains runtime state such as:

```text
generated tokens
KV cache
current position
generation configuration
finished status
```

Conceptually:

```text
state
 ↓
forward
 ↓
logits
 ↓
token selection
 ↓
new state
 ↓
repeat
```

---

### 7. Greedy decoding

Simplest strategy:

```text
logits
 ↓
argmax
 ↓
next token
```

The highest-scoring token is selected.

---

### 8. Sampling

Conceptually:

```text
logits
 ↓
temperature / filtering
 ↓
probabilities
 ↓
sample
 ↓
next token
```

Generation controls this behavior.

The Transformer itself still produces logits.

---

### 9. Beam search

Generation may maintain multiple candidate sequences:

```text
Beam 0
Beam 1
Beam 2
```

This requires:

* candidate management
* scoring
* pruning
* cache reordering

This demonstrates why cache operations need to be abstracted.

---

### 10. `generate()` vs `forward()`

```text
generate()
    ↓
repeated calls to
    ↓
forward()
```

`forward()` performs one model computation.

`generate()` coordinates the repeated computation required to produce a sequence.

---

### 11. Prefill vs Decode

Prefill:

```text
forward(prompt)
```

Processes many prompt tokens and initializes the cache.

Decode:

```text
forward(new_token)
forward(new_token)
forward(new_token)
...
```

Each decode step normally processes the newly generated token while reusing cached K/V state.

---

### 12. EOS and stopping

The Transformer produces logits.

Generation interprets the selected token.

If:

```text
next_token == EOS
```

generation may stop.

Similarly, generation can stop because of limits such as:

```text
max_new_tokens
```

Stopping is generation-level orchestration, not Transformer computation.

---

### 13. High-level architecture

```text
generate()
    ↓
model.forward()
    ↓
GemmaForCausalLM
    ↓
GemmaModel
    ↓
DecoderLayer × N
    ↓
Attention
    ├── RoPE
    └── Cache
          ↓
       K/V state
```

---

### 14. Code-reading strategy

When reading real generation code, identify the responsibility of each block:

```text
Input preparation
       ↓
Model forward
       ↓
Logits processing
       ↓
Token selection
       ↓
Cache/state update
       ↓
Position update
       ↓
Stopping check
       ↓
Repeat
```

Do not start by memorizing the entire `generate()` implementation.

Understand the responsibilities and data flow first.

---

### Core takeaway

> `generate()` is the orchestration layer that repeatedly invokes the model, uses its logits to select the next token, carries forward runtime state such as the KV cache, manages positions and stopping conditions, and continues until generation is complete.
