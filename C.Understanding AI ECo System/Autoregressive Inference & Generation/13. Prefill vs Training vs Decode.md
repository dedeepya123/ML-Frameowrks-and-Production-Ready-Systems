Lesson 14 — Training vs Prefill vs Decode
1. Three execution modes
Training
→ learn model parameters

Prefill
→ process the initial prompt and build KV cache

Decode
→ generate new tokens using the existing KV cache
2. Training
tokens
  ↓
Transformer
  ↓
logits
  ↓
loss
  ↓
backward
  ↓
parameter update

Characteristics:

gradients enabled
parameters updated
many tokens processed together
causal mask prevents future-token leakage
normal autoregressive training does not require persistent KV caching
3. Prefill

Example:

[A B C D]

The prompt is processed in one forward pass.

[A B C D]
    ↓
Transformer
    ↓
logits
+
KV cache

Characteristics:

inference
no gradients
parameters frozen
many prompt tokens processed together
KV cache is initialized
causal attention still applies
4. Decode

After prefill:

cache = [A B C D]

Next token:

E

Only the new token is passed to the model together with the cache.

E + cache(A,B,C,D)
        ↓
      model
        ↓
cache(A,B,C,D,E)
        ↓
logits

Then the next token is processed similarly.

5. Why KV caching matters

Without cache:

[A B C]
[A B C D]
[A B C D E]
[A B C D E F]
...

would repeatedly recompute old K/V.

With cache:

Prefill:
[A B C]

Decode:
D + cache

Decode:
E + cache

Decode:
F + cache

Previous K/V are reused.

6. Decode attention

Even though the model receives only one new token:

input = [E]

its query can attend to the entire cached history:

K/V = [A B C D E]

So:

One-token input does NOT mean one-token context.

The new query attends to the full available context.

7. Training vs Prefill vs Decode
	Training	Prefill	Decode
Purpose	Learn	Process prompt	Generate
Gradients	Yes	No	No
Parameters updated	Yes	No	No
Tokens/forward	Many	Many	Usually 1
KV cache	Usually no	Created	Reused/updated
Causal masking	Yes	Yes	Often implicit through available cache
Main pattern	Parallel	Parallel	Sequential across tokens
8. Position information

Prefill:

input_ids     = [A B C D]
position_ids  = [0 1 2 3]

Decode:

input_ids     = [E]
position_ids  = [4]
cache_position = [4]

Next:

input_ids     = [F]
position_ids  = [5]
cache_position = [5]
9. Decode flow
new token
   ↓
Q/K/V
   ↓
RoPE(position)
   ↓
cache.update()
   ↓
Q attends to historical + current K/V
   ↓
logits
   ↓
next token
10. Performance intuition

Prefill:

many tokens
→ high parallelism
→ large matrix operations
→ often compute-heavy

Decode:

one/few tokens
→ sequential token generation
→ growing KV cache
→ often more sensitive to memory bandwidth and latency

Exact bottlenecks depend on model, hardware, batch size, context length, and implementation.
