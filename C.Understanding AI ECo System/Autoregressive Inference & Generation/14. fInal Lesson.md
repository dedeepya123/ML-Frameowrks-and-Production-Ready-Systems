# Module 9 — Autoregressive Inference & Generation

## 1. Core execution modes

```text
Training
→ learn parameters

Prefill
→ process prompt + initialize KV cache

Decode
→ process new tokens + reuse/update KV cache
```

---

## 2. Generation architecture

```text
generate()
    ↓
prepare inputs
    ↓
model.forward()
    ↓
logits + cache
    ↓
select next token
    ↓
update generation state
    ↓
stopping check
    ↓
repeat
```

---

## 3. Prefill

For prompt:

```text
[A B C D]
```

conceptually:

```text
input_ids     = [A B C D]
position_ids  = [0 1 2 3]
```

The entire prompt is processed.

Result:

```text
logits
+
KV cache containing prompt K/V
```

---

## 4. Decode

After prefill:

```text
cache = A B C D
```

New token:

```text
E
```

Model receives conceptually:

```text
input_ids      = [E]
position_ids   = [4]
cache_position = [4]
cache          = previous K/V
```

The model computes the new Q/K/V, applies RoPE, updates the cache, performs attention, and produces logits.

---

## 5. Full sequence vs current model input

Generation may maintain:

```text
full generated sequence:
[A B C D E]
```

while the model receives only:

```text
current input:
[E]
```

Do not confuse these two.

---

## 6. `position_ids`

Represent logical token positions used by positional encoding.

Example:

```text
tokens:
[A B C D]

positions:
[0 1 2 3]
```

During decode:

```text
new token E
position = 4
```

---

## 7. `cache_position`

Tracks the logical sequence positions associated with the current tokens in the cache.

Conceptually:

```text
position_ids
→ positional encoding concern

cache_position
→ cache/runtime-state concern
```

For ordinary contiguous generation they often have the same values.

---

## 8. KV Cache

Concept:

```text
previous K/V states
```

Stored per decoder layer.

Conceptually:

```text
Layer 0 → K/V
Layer 1 → K/V
...
Layer N → K/V
```

Cache implementations can differ:

```text
DynamicCache
StaticCache
...
```

---

## 9. `generate()` vs `forward()`

```text
generate()
→ orchestration

forward()
→ one neural-network computation
```

Generation repeatedly invokes the model.

## 11. Real HF generation reading strategy

When opening production generation code, identify:

```text
1. Generation setup
2. Input preparation
3. Model invocation
4. Logits handling
5. Token selection
6. Cache/state update
7. Position update
8. Stopping
9. Next iteration
```

## 12. Data-flow reasoning method

For every important variable ask:

### Where was it born?

```text
Who created this object/tensor?
```

### What transformed it?

```text
Which class/function modified it?
```

### Who consumes it?

```text
Which function uses it next?
```

### What responsibility does it represent?

```text
model computation?
generation?
cache?
position?
token selection?
```

This is the preferred method for reading unfamiliar ML production code.

```text
generate()

    ├── cache_position
    ├── attention_mask

    ↓
GemmaModel.forward()
    ↓
DecoderLayer × N
    ↓
Attention

    ├── Cache.update()

LM head
    ↓
logits
    ↓
token selection
    ↓
generation state update
    ↓
repeat
```

## Core mental model

When seeing:

```python
generate(...)
```

think:

> "This is the outer orchestration loop."

When seeing:

```python
forward(...)
```

think:

> "This performs one model computation."

When seeing:

```python
cache
```

think:

> "This is accumulated K/V runtime state."

When seeing:

```python
position_ids
```

think:

> "These tell positional encoding which logical positions are being processed."

When seeing:

```python
cache_position
```

think:

> "This tells the cache/runtime where the current tokens belong."

When seeing:

```python
prepare_inputs_for_generation(...)
```

think:

> "This bridges generation state to the exact inputs required by the model's next forward call."

---

## Final takeaway

The important skill is not memorizing Hugging Face's `generate()` implementation.

The skill is being able to open the code and reconstruct:

```text
Where did this tensor/object come from?
        ↓
Why does this class need it?
        ↓
What transformation happens here?
        ↓
What does this function return?
        ↓
Who consumes that result next?
```

That is the code-reading and reasoning skill needed to understand model-specific implementations and production inference systems.
