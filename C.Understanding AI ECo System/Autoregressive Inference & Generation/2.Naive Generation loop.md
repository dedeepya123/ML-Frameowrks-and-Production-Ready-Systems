# Module 9 — Autoregressive Inference & Generation

## Lesson 3 — The Naïve Autoregressive Generation Loop

### 1. Simplest generation algorithm

```text
tokens
  ↓
model(tokens)
  ↓
logits at last position
  ↓
choose next token
  ↓
append token
  ↓
repeat
```

A naïve implementation passes the **entire sequence generated so far** through the model at every step.

Example:

```text
Step 1: A B C → D
Step 2: A B C D → E
Step 3: A B C D E → F
```

---

### 2. Where the redundancy occurs

Inside each Attention layer:

```text
Q = XWq
K = XWk
V = XWv
```

When generating a new token, the previous tokens have not changed.

Therefore their:

```text
K
V
```

values also have not changed.

But naïve generation recomputes them.

```text
Step 1:
A → K_A V_A
B → K_B V_B
C → K_C V_C

Step 2:
A → K_A V_A  ← recomputed
B → K_B V_B  ← recomputed
C → K_C V_C  ← recomputed
D → K_D V_D  ← new
```

This is redundant work.

---

### 3. Why cache K and V?

During decoding for the new token:

```text
Q_new
```

needs to attend to:

```text
K_previous + K_new
```

and:

```text
V_previous + V_new
```

Therefore previous K/V can be stored and reused.

The key attention equation is:

```text
Attention(Q,K,V)
=
softmax(QKᵀ / √d) V
```

For the current token, the query is new, while previous K/V can be reused.

---

### 4. Why not cache Q?

Q represents the query for the current token.

Each newly generated token produces a new query:

```text
Q_D
Q_E
Q_F
...
```

Previous queries are not needed for computing the current token's attention.

Therefore the standard cache is a **KV cache**, not a Q cache.

---

### 5. KV cache is per Transformer layer

Each decoder layer has its own attention projections, so each layer maintains its own K/V history.

Conceptually:

```text
Cache
├── Layer 0 → K, V
├── Layer 1 → K, V
├── Layer 2 → K, V
└── ...
```

The cache stores projected attention Keys and Values, not simply the complete previous hidden-state history.

---

### 6. KV cache does NOT eliminate the Transformer

During decoding, every new token still passes through the Transformer layers:

```text
new token
   ↓
Layer 0
   ↓
Layer 1
   ↓
...
Layer N
   ↓
LM Head
   ↓
logits
```

The optimization is that Attention reuses previously computed K/V instead of recomputing them.

---

### 7. Why KV cache matters for systems

KV cache can become a major memory and performance concern because it grows with:

```text
number of layers
×
number of KV heads
×
head dimension
×
sequence length
×
batch size
×
2 (K and V)
×
bytes per element
```

Therefore KV cache affects:

* GPU/device memory
* memory bandwidth
* maximum context length
* batching capacity
* inference latency
* throughput

### Core mental model

```text
Naïve generation
      ↓
full sequence processed repeatedly
      ↓
old K/V recomputed
      ↓
wasted computation
      ↓
KV cache
      ↓
store old K/V
      ↓
reuse them during decoding
```

### Most important takeaway

When seeing:

```python
past_key_values
```

think:

> Previously computed attention K/V history used to avoid recomputation during autoregressive decoding.

When seeing:

```python
DynamicCache
```

think:

> A runtime abstraction for managing the growing KV-cache state.
