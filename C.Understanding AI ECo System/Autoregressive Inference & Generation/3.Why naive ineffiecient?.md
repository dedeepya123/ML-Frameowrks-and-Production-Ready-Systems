# Module 9 — Autoregressive Inference & Generation

## Lesson 4 — Why the Naïve Approach Is Inefficient

### 1. Naïve generation

For a prompt of length `S`, each generation step passes the entire sequence so far through the Transformer.

Example:

```text
Prompt = 10 tokens
Generate = 5 tokens

Step 1 → 10 tokens
Step 2 → 11 tokens
Step 3 → 12 tokens
Step 4 → 13 tokens
Step 5 → 14 tokens
```

This repeatedly recomputes the previous tokens.

---

### 2. Redundant K/V computation

Attention computes:

```text
Q = XWq
K = XWk
V = XWv
```

When a new token is generated, previous tokens have not changed.

Therefore their K/V values have not changed either.

Naïve generation recomputes them unnecessarily.

---

### 3. Full-sequence attention

For sequence length `S`:

```text
Q → [S, d]
K → [S, d]

QKᵀ → [S, S]
```

The attention-score computation therefore has quadratic dependence on sequence length:

[
O(S^2d)
]

for the score multiplication.

---

### 4. Cached decoding

During decoding, only the new token produces a new query:

```text
Q_new → [1, d]
```

The cached K/V contain the previous sequence:

```text
K_cache → [S, d]
V_cache → [S, d]
```

Therefore:

```text
Q_new K_cacheᵀ → [1, S]
```

The attention-score computation for the current token is approximately:

[
O(Sd)
]

rather than recomputing full `[S, S]` attention for the whole sequence.

Important:

> KV cache does not make decoding independent of context length. The new token still attends over the growing cached sequence.

---

### 5. KV cache tradeoff

KV caching trades:

```text
computation
```

for:

```text
memory
```

Without cache:

```text
low persistent KV memory
+
large recomputation
```

With cache:

```text
larger runtime memory
+
much less redundant computation
```

---

### 6. KV-cache memory

Conceptually, cache memory grows with:

```text
batch
× layers
× KV heads
× sequence length
× head dimension
× 2 (K and V)
× bytes per element
```

Therefore longer context means larger KV-cache memory.

---

### 7. Prefill vs Decode

**Prefill:**

```text
whole prompt
     ↓
many queries × many keys
     ↓
build KV cache
```

**Decode:**

```text
one new token
     ↓
one new query
     ↓
attend to cached K/V
     ↓
produce next token
```

The key distinction:

```text
Prefill → many tokens processed together
Decode  → one token processed at a time
```

---

### 8. Core reasoning chain

```text
Autoregressive generation
        ↓
naïve full-sequence recomputation
        ↓
old K/V repeatedly recomputed
        ↓
old K/V do not change
        ↓
cache old K/V
        ↓
new token produces new Q/K/V
        ↓
new Q attends to cached K/V
        ↓
decode becomes much more efficient
        ↓
but KV cache consumes memory
```

### Most important takeaway

> KV cache is fundamentally a memory-for-computation tradeoff that avoids recomputing attention history during autoregressive decoding.
