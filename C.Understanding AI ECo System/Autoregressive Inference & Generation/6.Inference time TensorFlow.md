# Module 9 — Autoregressive Inference & Generation

## Lesson 8 — Inference-Time Tensor Flow

### 1. High-level flow

```text
input_ids
    ↓
Embedding
    ↓
inputs_embeds
    ↓
Decoder Layers
    ↓
Final Norm
    ↓
LM Head
    ↓
logits
    ↓
generation logic
    ↓
next token
```

---

### 2. `input_ids`

Discrete token IDs.

Typical shape:

```text
[B, S]
```

They are indices into the embedding table.

---

### 3. `inputs_embeds`

Result of embedding lookup.

Typical shape:

```text
[B, S, hidden_size]
```

Each token ID becomes a continuous vector.

---

### 4. `hidden_states`

The representation flowing through the Transformer.

Typical decode shape:

```text
[B, 1, hidden_size]
```

During prefill:

```text
[B, S, hidden_size]
```

---

### 5. Attention flow

```text
hidden_states
      ↓
Q / K / V projections
      ↓
RoPE on Q/K
      ↓
KV cache update
      ↓
Attention
      ↓
attention output
```

During decode:

```text
Q_new
[B, H, 1, D]

K_cache
[B, H_kv, S, D]

V_cache
[B, H_kv, S, D]
```

The new query attends over the entire cached history.

---

### 6. Decoder layer

Conceptually:

```text
hidden_states
      ↓
Normalization
      ↓
Attention
      ↓
Residual
      ↓
Normalization
      ↓
MLP
      ↓
Residual
      ↓
hidden_states
```

The output becomes the input to the next decoder layer.

---

### 7. KV cache

Each decoder layer maintains its own K/V state:

```text
Layer 0 → K₀/V₀
Layer 1 → K₁/V₁
...
Layer N → Kₙ/Vₙ
```

During decode:

```text
K_new/V_new
    ↓
cache.update(...)
    ↓
K_cache/V_cache
```

---

### 8. Final output

After the final decoder layer:

```text
hidden_states
    ↓
final normalization
    ↓
LM Head
    ↓
logits
```

Typical decode logits shape:

```text
[B, 1, vocab_size]
```

Logits are raw vocabulary scores, not probabilities.

---

### 9. Model vs generation orchestration

Important abstraction boundary:

```text
MODEL
input_ids
    ↓
Transformer
    ↓
logits

GENERATION SYSTEM
logits
    ↓
sampling / argmax
    ↓
next token
    ↓
call model again
```

The model primarily computes scores.

The generation system orchestrates repeated inference steps and decides how to select tokens.

---

### 10. Persistent vs temporary state

Conceptually persistent across decoding steps:

```text
model weights
KV cache
```

Current-step/temporary computation:

```text
input_ids
inputs_embeds
hidden_states
Q
K_new
V_new
attention scores
attention probabilities
MLP intermediates
logits
```

---

### 11. Prefill vs Decode tensor difference

Prefill:

```text
[B, S, hidden_size]
```

Decode:

```text
[B, 1, hidden_size]
```

Prefill processes the existing sequence.

Decode processes the new position while reusing cached history.

---

### 12. Code-reading mental model

When reading inference code:

```text
input_ids
→ What tokens?

inputs_embeds
→ What token vectors?

hidden_states
→ What representation is flowing?

query/key/value_states
→ Attention projections?

position_ids/cache_position
→ Where are these tokens positioned?

past_key_values/cache
→ What previous attention state is being reused?

logits
→ What vocabulary scores did the model produce?

next_token
→ What did generation choose?
```

### Core takeaway

> Follow the tensor, not the class name. For every tensor ask: who produced it, what does it represent, what is its shape, who consumes it, and whether it persists across decoding steps.
