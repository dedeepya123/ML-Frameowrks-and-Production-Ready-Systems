# Module 9 — Autoregressive Inference & Generation

## Lesson 5 — KV Cache

### 1. What is KV Cache?

KV cache stores previously computed **Keys and Values** from Attention so they can be reused during autoregressive decoding.

For one layer:

```text
K_cache = [K₁, K₂, ..., Kₙ]
V_cache = [V₁, V₂, ..., Vₙ]
```

When a new token arrives:

```text
Q_new, K_new, V_new
```

are computed and:

```text
K_cache ← K_cache + K_new
V_cache ← V_cache + V_new
```

---

### 2. Why cache K and V?

Attention:

[
Attention(Q,K,V)
================

softmax\left(\frac{QK^T}{\sqrt d}\right)V
]

The new query needs the previous keys to determine relevance and the previous values to retrieve information.

Therefore previous K/V are reusable.

---

### 3. Why not cache Q?

Q represents the query for the current token.

At every decoding step:

```text
Q_new
```

is different.

Previous Q values are not needed to calculate the current token's attention output.

Therefore:

```text
K/V → persistent history
Q   → current temporary query
```

---

### 4. Multi-head cache

With multiple attention heads, K/V are maintained for each KV head.

Logical shape may be:

```text
[B, H_kv, S, D]
```

where:

* `B` = batch size
* `H_kv` = number of K/V heads
* `S` = cached sequence length
* `D` = head dimension

Actual dimension ordering can differ between implementations.

Always reason about what each dimension means instead of memorizing layout.

---

### 5. Cache is per Transformer layer

Each decoder layer has different K/V projection weights.

Therefore each layer maintains its own K/V cache:

```text
Cache
├── Layer 0 → K₀, V₀
├── Layer 1 → K₁, V₁
├── Layer 2 → K₂, V₂
└── ...
```

---

### 6. Cache grows with sequence length

After prompt:

```text
A B C
```

cache contains:

```text
K_A K_B K_C
V_A V_B V_C
```

After generating `D`:

```text
K_A K_B K_C K_D
V_A V_B V_C V_D
```

After generating `E`:

```text
K_A K_B K_C K_D K_E
V_A V_B V_C V_D V_E
```

Therefore KV-cache size grows approximately linearly with sequence length.

---

### 7. KV cache is runtime state

Model weights:

```text
learned during training
```

KV cache:

```text
created during inference
depends on the current request/context
```

KV cache is not model parameters and does not contain token IDs.

It contains floating-point K/V tensors derived from model computation.

---

### 8. Prefill

The complete prompt is processed:

```text
prompt
   ↓
Transformer
   ↓
K/V for all prompt positions
   ↓
KV cache
```

This creates the initial attention history.

---

### 9. Decode

After prefill, each new position is processed:

```text
new token
   ↓
Q_new, K_new, V_new
   ↓
append K_new/V_new to cache
   ↓
Q_new attends to cached K/V
   ↓
next hidden state
   ↓
logits
   ↓
next token
```

For a single sequence, decode processes one new position at a time.

For a batch, this means one new position per active sequence.

---

### 10. MHA vs GQA/MQA

KV-cache memory depends on the number of **KV heads**.

With GQA:

```text
Q heads > KV heads
```

Multiple query heads share K/V heads.

Therefore GQA can substantially reduce KV-cache memory compared with full multi-head attention.

---

### 11. Core mental model

```text
Previous tokens
      ↓
compute K/V
      ↓
store in cache
      ↓
new token
      ↓
compute Q/K/V
      ↓
append new K/V
      ↓
new Q attends to cached K/V
      ↓
next token
```

### Most important takeaway

> KV cache is the persistent attention history for the current inference sequence: previous K/V are stored per Transformer layer and reused when generating subsequent tokens.


"Explain KV cache."
During autoregressive decoding, previous tokens don't change. Their projected Keys and Values at each Transformer layer therefore don't need to be recomputed. We store those K/V tensors in a per-layer cache. When a new token arrives, we compute its new Q/K/V, append its K/V to the cache, and use the new Q to attend over the cached K/V history. This allows decoding to process only the new position rather than recomputing the entire sequence.
