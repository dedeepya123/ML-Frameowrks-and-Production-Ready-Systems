# Module 9 — Autoregressive Inference & Generation

## Lesson 11 — `DynamicCache`

### 1. What is `DynamicCache`?

`DynamicCache` is a cache implementation that maintains K/V attention state for each decoder layer while the cached sequence length grows during generation.

Conceptually:

```text
DynamicCache
│
├── Layer 0 → K₀/V₀
├── Layer 1 → K₁/V₁
├── Layer 2 → K₂/V₂
└── ...
```

---

### 2. Why "dynamic"?

The cached sequence length grows as new tokens are generated.

```text
Prompt:      S = 100
Decode 1:    S = 101
Decode 2:    S = 102
Decode 3:    S = 103
```

The model architecture does not change; the runtime K/V state grows.

---

### 3. Tensor shape intuition

Typical conceptual shape:

```text
[B, H, S, D]
```

where:

* `B` = batch
* `H` = KV heads
* `S` = cached sequence length
* `D` = head dimension

New token:

```text
[B, H, 1, D]
```

After update:

```text
[B, H, S+1, D]
```

---

### 4. Per-layer cache

Each decoder layer has independent K/V state:

```text
Layer 0 → K₀/V₀
Layer 1 → K₁/V₁
...
Layer N → Kₙ/Vₙ
```

`layer_idx` identifies which layer's cache should be updated.

---

### 5. Conceptual update

Before:

```text
K_cache = K₀ ... Kₜ
V_cache = V₀ ... Vₜ
```

Current token produces:

```text
K_new
V_new
```

After update:

```text
K_total = [K_cache | K_new]
V_total = [V_cache | V_new]
```

The exact implementation does not necessarily perform a physical `torch.cat()` every step.

---

### 6. Why don't we cache Q?

During decoding, we need the query for the current token.

Historical queries are not required again.

Therefore:

```text
K/V → cached
Q   → computed for current step
```

---

### 7. Prefill + DynamicCache

During prefill:

```text
Prompt
  ↓
K/V for all prompt positions
  ↓
cache initialized
```

During decode:

```text
new token
  ↓
new K/V
  ↓
cache grows
```

Therefore the cache bridges prefill and decode.

---

### 8. Why not simply concatenate forever?

A naïve implementation could do:

```python
new_cache = torch.cat([old_cache, new_kv], dim=-2)
```

but repeated reallocation/copying can be expensive.

Production implementations may use different storage/update strategies.

This is one reason the `Cache` abstraction is valuable.

---

### 9. Algorithmic vs systems view

Algorithmic view:

```text
append K/V
```

Systems view:

```text
How is memory allocated?
Is data copied?
Can memory be reused?
What is the layout?
Where is the memory?
How much bandwidth is required?
```

These are different levels of reasoning.

---

### 10. DynamicCache is runtime infrastructure

It does not contain model weights.

```text
Model weights:
learned, persistent, shared

KV cache:
runtime-generated, temporary, request-specific
```

---

### 11. Code-reading mapping

When seeing:

```python
cache.update(
    key_states,
    value_states,
    layer_idx
)
```

reason:

```text
key_states/value_states
        ↓
current layer's new K/V
        ↓
layer_idx identifies the layer
        ↓
cache updates stored history
        ↓
returns K/V state needed by attention
```

---

### 12. Conceptual forward flow

```text
hidden states
      ↓
Q/K/V projections
      ↓
RoPE
      ↓
current K/V
      ↓
Cache.update()
      ↓
past + current K/V
      ↓
attention
      ↓
output
```

---

### 13. Dynamic vs Static intuition

Dynamic cache:

```text
100 → 101 → 102 → 103
```

Static cache:

```text
fixed capacity
[████████░░░░░░░]
```

Dynamic cache grows with actual sequence length.

Static cache allocates capacity ahead of time.

---

### Core takeaway

> `DynamicCache` manages per-layer K/V attention state whose effective sequence length grows as new tokens are processed. The rest of the Transformer interacts with the cache abstraction rather than needing to know the underlying memory-management details.

## One last mental check

When you see this in model code:

```python
key_states, value_states = past_key_values.update(
    key_states,
    value_states,
    self.layer_idx,
)
```

you should now be able to mentally expand it to:

```text
"Attention has just computed K/V for the current positions.
Give those K/V tensors to the cache for this decoder layer.
The cache combines/manages them with the previously stored
K/V history and gives attention the K/V state it needs."
```

That's the level of **code ↔ concept mapping** we're aiming for.
