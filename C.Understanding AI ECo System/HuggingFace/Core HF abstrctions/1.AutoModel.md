# AutoModel

## Why does it exist?

Different Transformer architectures have different implementation classes.

Examples:
- BertModel
- GemmaModel
- LlamaModel
- T5Model

Without AutoModel, users must know:
- Which architecture a checkpoint belongs to.
- Which Python class to import.
- Which class to instantiate.

AutoModel moves this responsibility from the user to the library.

---

## Problem

Checkpoint
      ↓
User must determine architecture
      ↓
Import correct class
      ↓
Instantiate model

---

## Solution

Checkpoint
      ↓
Read configuration
      ↓
Determine model_type
      ↓
Instantiate correct model class
      ↓
Return PyTorch nn.Module

---

## Mental Model

AutoModel is **not** a neural network.

It is a **factory/dispatcher** that selects the correct model implementation based on the pretrained model's configuration.

---

## Internal Flow

AutoModel.from_pretrained(...)
        ↓
Download model package
        ↓
Read configuration
        ↓
Identify model_type
        ↓
Instantiate correct model class
        ↓
Load pretrained weights
        ↓
Return ready-to-use nn.Module

---

## Design Pattern

Closely resembles the Factory Pattern.

The caller requests a model.

The library decides which concrete implementation to create.

---

## Key Takeaways

- AutoModel hides architecture-specific class selection.
- It improves scalability and usability.
- The returned object is the actual model implementation (e.g., GemmaModel), which inherits from nn.Module.
- All PyTorch APIs continue to work because the returned object is a normal PyTorch model.

**Why does AutoModel exist?**

A good answer would be:
Different Transformer architectures have different implementation classes such as GemmaModel, BertModel, and LlamaModel. Without AutoModel, users would need to know which class matches every checkpoint. AutoModel removes that burden by reading the model's configuration, identifying the architecture, instantiating the correct model class, loading the pretrained weights, and returning a standard PyTorch nn.Module
