# AutoConfig

## Why does it exist?

Configuration is useful independently of the neural network.

Many engineering tasks require only architecture metadata, not the model or its weights.

Examples:
- Inspect hidden size
- Check number of layers
- Validate compatibility
- Convert configurations
- Compare architectures

---

## What is Configuration?

Configuration describes how to build the model.

Examples:
- hidden_size
- num_hidden_layers
- num_attention_heads
- vocab_size

It does **not** contain:
- Learned weights
- Buffers
- Forward logic

---

## AutoConfig Responsibility

AutoConfig loads the architecture metadata and returns the correct configuration object.

Conceptual flow:

Repository
      ↓
Read configuration
      ↓
Determine model_type
      ↓
Instantiate Config class
      ↓
Return Config object

---

## Relationship

AutoConfig → Returns GemmaConfig, BertConfig, etc.

AutoModel → Returns GemmaModel, BertModel, etc.

Configuration describes the architecture.

The model implements the architecture.

---

## Key Takeaways

- Configuration is independent from weights.
- AutoConfig avoids constructing large models when only metadata is needed.
- AutoConfig is a factory for configuration objects.
- Configuration acts as the blueprint for building the neural network.

**Why does AutoConfig exist?**
A model's architecture description is useful independently of the model itself. Engineers often need to inspect, validate, compare, or modify architecture metadata without constructing the neural network or loading its weights. AutoConfig provides a standard way to load that metadata and return the correct configuration object for the model architecture.
