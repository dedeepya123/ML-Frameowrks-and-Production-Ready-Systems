# AutoProcessor

## Why does it exist?

Different AI models accept different input modalities:

- Text
- Images
- Audio
- Video
- Combinations of these

A tokenizer is only responsible for text.

AutoProcessor provides a unified way to prepare inputs for models, especially multimodal ones.

---

## Responsibilities

Tokenizer:
- Text → Token IDs

Image Processor:
- Image → Pixel Tensor

Feature Extractor:
- Audio → Feature Tensor

Processor:
- Coordinate the required preprocessing components.

---

---

## Key Takeaways

- AutoProcessor is not a replacement for AutoTokenizer.
- It provides a unified preprocessing interface.
- It is most useful for multimodal models.
- It coordinates the preprocessing components required by a model.

**Why do we need AutoProcessor if we already have AutoTokenizer?**

A good answer is:

AutoTokenizer is designed specifically for text. Modern AI models may accept images, audio, video, or combinations of these modalities. AutoProcessor provides a unified abstraction that loads and coordinates the appropriate preprocessing components for a particular model, giving users one consistent interface regardless of the input modalities.
