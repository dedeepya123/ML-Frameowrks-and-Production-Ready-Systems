# Module 3 — Transformer Inference Cost
## Lesson 3 — Attention Computation

## 1. What is attention trying to do?

Attention allows each token to:

1. Determine which other tokens are relevant.
2. Retrieve information from those tokens.

The two conceptual pieces are:

    Q · K
        ↓
    relevance

    attention_weights × V
        ↓
    retrieved information

---

## 2. Attention pipeline

Given Q, K, V:

    Q
     \
      → QKᵀ
     /
    K

        ↓

    scale by 1 / √d

        ↓

    causal mask (decoder-only)

        ↓

    softmax

        ↓

    attention weights

        ↓

    attention weights × V

        ↓

    attention output

---

## 3. QKᵀ

For one head:

    Q = [S,d]
    K = [S,d]

Therefore:

    Kᵀ = [d,S]

and:

    QKᵀ

    [S,d] × [d,S]

produces:

    [S,S]

Each element represents the score between one query and one key.

---

## 4. Why is attention quadratic?

The attention score matrix has:

    S × S

elements.

Therefore:

    O(S²)

memory for the score matrix if materialized.

The interaction computation costs approximately:

    2S²d

FLOPs per head.

Across H heads:

    2HS²d

Since:

    D = H × d

this becomes:

    ~2S²D

---

## 5. Scaling

Attention scores are scaled:

    scores = QKᵀ / √d

The scaling prevents dot-product magnitudes from becoming too large
as head dimension increases.

The scaling itself is relatively cheap compared with the matrix
multiplications.

---

## 6. Causal masking

Decoder-only Transformers must prevent a token from seeing future
tokens.

Conceptually:

    q1 → k1
    q2 → k1,k2
    q3 → k1,k2,k3
    q4 → k1,k2,k3,k4

Future positions are masked.

A mathematical implementation may represent masked positions as
very negative values before softmax.

A production implementation does not necessarily have to materialize
a separate full mask tensor.

---

## 7. Softmax

Softmax converts attention scores into normalized weights:

    softmax(x_i) = exp(x_i) / Σ exp(x_j)

Conceptually:

    scores
      ↓
    softmax
      ↓
    normalized attention weights

Softmax involves exponentials, reductions, and division.

Although its arithmetic count is smaller than the major matrix
multiplications, memory movement can matter significantly.

---

## 8. Attention × V

After softmax:

    A = softmax(QKᵀ / √d)

Then:

    output = AV

Shapes:

    A = [S,S]
    V = [S,d]

Therefore:

    [S,S] × [S,d]

produces:

    [S,d]

Cost:

    ~2S²d

FLOPs per head.

Across heads:

    ~2S²D

---

## 9. Attention interaction compute

Two major matrix multiplications:

    QKᵀ ≈ 2S²D

    AV  ≈ 2S²D

Therefore:

    Attention interaction compute
    ≈ 4S²D

ignoring other operations and implementation-specific details.

---

## 10. Compare with Q/K/V projections

Q/K/V projection cost:

    ≈ 6SD²

for standard MHA.

Attention interaction cost:

    ≈ 4S²D

Therefore:

    Projection:
        ~SD²

    Attention interaction:
        ~S²D

The relative importance depends strongly on:

    S vs D

For long sequences, the S² term becomes increasingly important.

---

## 11. Naive attention memory problem

A naive implementation may materialize:

    scores = QKᵀ

with shape:

    [B,H,S,S]

and then:

    weights = softmax(scores)

also:

    [B,H,S,S]

For long sequences this can be enormous.

Example:

    B = 1
    H = 32
    S = 4096
    dtype = FP16

One [S,S] matrix:

    4096² elements
    ≈ 16.8 million elements

At FP16:

    ≈ 32 MiB

Across 32 heads:

    ≈ 1 GiB

if all head matrices were materialized simultaneously.

This illustrates why naive attention has a serious memory problem.

---

## 12. Important distinction

"Attention is quadratic" can refer to different things.

### Compute

    O(S²D)

for attention interactions.

### Intermediate memory

    O(S²)

if the attention matrix is materialized.

### Actual runtime

Depends on:

- kernel implementation
- tiling
- memory hierarchy
- memory bandwidth
- hardware compute
- fusion
- dtype
- runtime/compiler

These should not be treated as the same concept.

---

## 13. Naive implementation

Conceptually:

    scores = Q @ K.transpose(-2, -1)

    scores = scores / sqrt(d)

    scores = scores + causal_mask

    weights = softmax(scores, dim=-1)

    output = weights @ V

This implementation is excellent for understanding the mathematics.

However, it may materialize large intermediate tensors.

---

## 14. Model → runtime → NPU

At model/framework level:

    Q @ Kᵀ
    softmax
    weights @ V

may correspond to multiple operators:

    MatMul
    Scale
    Mask
    Softmax
    MatMul

A simple implementation might execute these as separate kernels.

That can cause:

    intermediate write
        ↓
    memory
        ↓
    intermediate read
        ↓
    next kernel

An optimized implementation may fuse or restructure these operations.

---

## 15. Why optimization is possible

The mathematical result is:

    softmax(QKᵀ / √d)V

But we do not necessarily need to materialize the entire:

    [S,S]

matrix.

We can potentially:

- tile Q/K/V
- compute smaller blocks
- keep intermediate data closer to compute
- fuse operations
- avoid unnecessary global-memory traffic

This leads to:

    Memory-efficient attention
          ↓
    FlashAttention
          ↓
    Tiling

---

## 16. Prefill vs Decode preview

### Prefill

For a sequence of length S:

    Q = [S,d]
    K = [S,d]
    V = [S,d]

and:

    QKᵀ → [S,S]

Large all-to-all interaction.

### Decode

For a new token:

    Q_new = [1,d]

while previous K/V are cached:

    K_cache = [S,d]
    V_cache = [S,d]

Then:

    Q_new @ K_cacheᵀ

becomes:

    [1,d] × [d,S]
        ↓
    [1,S]

This is fundamentally different from prefill.

The detailed prefill/decode analysis comes later.

---

## 17. How to reason about attention in real code

When you see:

    attention(q, k, v)

ask:

1. What are Q/K/V shapes?
2. What is the number of heads?
3. What is head dimension?
4. What does QKᵀ produce?
5. Is [S,S] materialized?
6. What masking is applied?
7. Where does softmax happen?
8. What does the second MatMul do?
9. Which intermediates are written to memory?
10. Which operations are fused?
11. Which runtime operators represent attention?
12. Which kernels execute them?
13. What does the NPU do?
14. Is the bottleneck compute or memory?
15. Are we in prefill or decode?

---

## 18. Core mental model

    Q                  K
     \                /
      \              /
       └─── QKᵀ ─────┘
             │
             ▼
        [S × S scores]
             │
        scale/mask
             │
             ▼
          softmax
             │
             ▼
     attention weights
             │
             │
             ▼
            × V
             │
             ▼
      attention output

Underneath:

    MODEL
    Attention mathematics
        ↓
    TENSOR
    [S,d] × [d,S] → [S,S]
        ↓
    COMPUTE
    O(S²D)
        ↓
    MEMORY
    potentially O(S²) intermediate
        ↓
    RUNTIME
    MatMul + Softmax + MatMul
        ↓
    KERNEL
    separate or fused implementations
        ↓
    NPU
    compute + memory hierarchy

---

## 19. Core takeaway

Attention is not simply "one operation."

It is a sequence of computations:

    QKᵀ
      ↓
    scale
      ↓
    mask
      ↓
    softmax
      ↓
    × V

The important systems problem is that the mathematically natural
implementation can materialize a huge [S,S] intermediate.

Therefore attention optimization is often about more than reducing
FLOPs.

A major goal is:

    reduce unnecessary memory traffic
    while preserving the same mathematical result.

This is the foundation for understanding memory-efficient attention,
FlashAttention, and tiling.
