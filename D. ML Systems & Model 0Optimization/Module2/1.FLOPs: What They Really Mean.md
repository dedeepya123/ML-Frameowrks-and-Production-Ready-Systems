# Module 2 — Compute vs Memory

## Lesson 1 — FLOPs: What They Really Mean

## 1. FLOP

FLOP = Floating-Point Operation.

Examples:

addition
multiplication
subtraction
division

Exact counting depends on the convention.

---

## 2. FLOPs vs FLOP/s

FLOPs:
Amount of computation.

FLOP/s:
Rate at which computation is performed.

Example:

10 GFLOPs workload
100 GFLOP/s hardware

Compute-only theoretical time:

10 / 100 = 0.1 s = 100 ms

Actual runtime can be higher.

---

## 3. Matrix multiplication

X = [M × K]
W = [K × N]
Y = XW

Approximate FLOPs:

FLOPs ≈ 2MKN

Reason:

Each output element performs approximately K multiplications and K additions.

---

## 4. Transformer projections

For:

X = [T × D]
W = [D × D]

Projection FLOPs:

≈ 2TD²

This applies conceptually to Q/K/V/output projections.

---

## 5. Attention computation

Full-sequence attention contains:

QKᵀ
and
AttentionWeights × V

Each is approximately:

2T²D FLOPs

So attention interaction is approximately:

O(T²D)

while many projection/MLP operations scale approximately:

O(TD²)

---

## 6. FLOPs do NOT equal runtime

Runtime also depends on:

- memory traffic
- memory bandwidth
- arithmetic intensity
- kernel efficiency
- tensor shapes
- parallelism
- hardware utilization
- synchronization
- launch overhead

Therefore:

FLOPs != latency.

---

## 7. Arithmetic intensity

Arithmetic intensity measures:

FLOPs / Bytes moved

Formula:

Arithmetic Intensity =
FLOPs / Bytes

High arithmetic intensity:
Lots of computation per byte.

Low arithmetic intensity:
Little computation per byte.

---

## 8. Compute-bound vs memory-bound

Low arithmetic intensity:

→ memory/bandwidth may limit performance.

High arithmetic intensity:

→ compute may limit performance.

This is a useful starting model, not an absolute rule.

---

## 9. GEMM

GEMM =
General Matrix-Matrix Multiplication.

Conceptually:

C = A × B

Transformer projections and many MLP operations are implemented using GEMM-like operations.

---

## 10. Prefill vs Decode

Prefill:

- many tokens
- larger matrix operations
- lots of parallel work
- compute utilization can be high

Decode:

- usually one/few new tokens per step
- smaller/skinny matrix operations
- less parallelism
- memory movement/cache behavior can become more important

Same model, different execution characteristics.

---

## 11. Batching

Batch 1:

[1 × D] × [D × D]

Batch 32:

[32 × D] × [D × D]

Larger batch can expose more parallelism and improve hardware utilization.

This can improve throughput.

---

## 12. Precision

FP32:
4 bytes/value

FP16/BF16:
2 bytes/value

INT8:
1 byte/value

Lower precision can reduce:

- memory footprint
- memory traffic

and may increase compute throughput if hardware supports it efficiently.

But it can introduce:

- numerical differences
- accuracy tradeoffs
- conversion overhead
- kernel/runtime constraints

---

## 13. Fusion

Separate:

RMSNorm
→ Activation
→ Scale

may cause multiple reads/writes.

Fusion can conceptually do:

read once
→ RMSNorm
→ Activation
→ Scale
→ write once

Main benefit may be reduced memory movement rather than reduced FLOPs.

---

## 14. Peak vs achieved FLOP/s

Peak FLOP/s:

Theoretical hardware capability.

Achieved FLOP/s:

What the workload actually reaches.

Low achieved FLOP/s does not automatically mean poor kernel implementation.

The workload may be:

- memory-bound
- too small
- poorly shaped
- limited by overhead
- insufficiently parallel

---

## 15. Core mental model

For an operation ask:

1. How many FLOPs?
2. How many bytes moved?
3. What is FLOPs/byte?
4. What is the hardware's compute capability?
5. What is its memory bandwidth?
6. Is the workload compute-bound or memory-bound?
7. How efficiently is the kernel using hardware?

---

## Key takeaway

FLOPs tell us:

"How much arithmetic work exists?"

They do NOT directly tell us:

"How fast will this run?"

To reason about performance, combine:

FLOPs
+
Bytes moved
+
Arithmetic intensity
+
Hardware compute
+
Memory bandwidth
+
Kernel efficiency

This is the foundation for understanding real ML inference performance.
