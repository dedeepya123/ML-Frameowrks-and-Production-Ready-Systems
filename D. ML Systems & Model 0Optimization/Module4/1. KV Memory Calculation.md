# Module 4 — Lesson 1: KV Cache Memory Calculation

## Core Idea

KV cache stores K and V for previous tokens so decode does not recompute them.

For each layer:

K/V shape:
[B, Hkv, L, Dh]

## General Formula

KV bytes =
2 × B × N × L × Hkv × Dh × dtype_bytes

Where:

- 2 = K + V
- B = batch size
- N = number of Transformer layers
- L = context length
- Hkv = number of KV heads
- Dh = head dimension
- dtype_bytes = bytes per KV element

## MHA

For MHA:

Hkv = H

and:

D = H × Dh

Therefore:

KV bytes = 2 × B × N × L × D × dtype_bytes

## Important Scaling

KV cache grows linearly with:

- batch size
- context length
- number of layers
- number of KV heads
- head dimension
- bytes per element

## Example

B=1
L=4096
Hkv=32
Dh=128
N=32
FP16

KV cache ≈ 2 GiB.

## GQA / MQA

GQA/MQA reduce Hkv.

Fewer KV heads → smaller KV cache.

Example:

MHA: 32 KV heads
GQA: 8 KV heads

GQA uses ~1/4 of the KV memory of MHA.

## Systems Insight

KV cache is not just model state.

It is a serving resource.

KV memory affects:

- maximum context
- batch size
- concurrency
- memory capacity
- memory bandwidth

## Important Distinction

KV capacity:
How much memory does the cache occupy?

KV bandwidth:
How much cache data must be read during decode?

Capacity is studied here.

Bandwidth will be studied later.

## Reasoning Rule

When KV memory is too large, inspect:

B, L, N, Hkv, Dh, dtype.

Possible optimization directions:

- reduce concurrency/batch
- manage context length
- GQA/MQA
- KV quantization
- memory-efficient cache management
