# Module 4 — Lesson 4: Batch Size vs KV Cache

## Core Idea

Increasing batch size can improve accelerator utilization because
more tokens are processed together and model weights are reused.

But every active sequence has its own KV cache.

Therefore:

KV memory ∝ batch size

## Compute Benefit

Batch ↑
→ larger matrix operations
→ better weight reuse
→ potentially higher arithmetic intensity
→ better accelerator utilization
→ higher throughput

## Memory Cost

Batch ↑
→ KV cache ↑
→ KV traffic ↑
→ memory capacity/bandwidth pressure ↑

## Variable-Length Requests

Different requests can have different context lengths.

Therefore:

Total KV memory ≈ sum(KV memory of active requests)

Not simply:

B × one fixed cache size.

## Serving Insight

Inference batch is a dynamic collection of active sequences.

Requests:
- arrive at different times
- have different context lengths
- finish at different times

Therefore real serving systems need scheduling and dynamic/continuous batching.

## Latency vs Throughput

Larger batches can improve total throughput without
necessarily improving individual-request latency.

## Key Reasoning

Increasing batch size is beneficial until another resource
becomes the bottleneck:

- compute
- memory capacity
- memory bandwidth
- scheduling/runtime overhead

Therefore:

"Bigger batch = faster" is incomplete.

Correct reasoning:

"Batch size trades compute utilization against memory,
bandwidth, latency, and capacity."
