# Module 5 — Part 2: Quantization Mathematics → Runtime

## Core Relationship

Symmetric:

x ≈ s × q

q ≈ x / s

Asymmetric:

x ≈ s × (q - z)

where:
- q = quantized integer
- s = scale
- z = zero-point

## Quantized Tensor

A quantized tensor is not just integer data.

It conceptually consists of:

INT data + quantization metadata

Metadata may include:
- scale
- zero-point
- quantization axis/group information

## Important Runtime Idea

Representation:
What is stored?

Computation:
What datatype does the kernel compute with?

Accumulation:
What datatype stores intermediate results?

These can be different.

## Example: W8A8

Weights = INT8
Activations = INT8

Conceptually:

INT8 × INT8
→ wider accumulation (often INT32)
→ scaling/requantization
→ output

## Example: W4A16

Weights = INT4
Activations = FP16

This is weight-only quantization.

Implementation depends on kernel/hardware:
- unpack/dequantize
- or native low-bit computation

## Systems Connection

Quantization can reduce:

- model memory
- memory bandwidth
- potentially compute cost

But speedup depends on:
- hardware support
- kernels
- bottleneck
- conversion overhead
- accuracy requirements

## Key Questions

When seeing a quantized model ask:

1. What datatype is stored?
2. What datatype is computed?
3. What datatype is used for accumulation?
4. Where are scale/zero-point applied?
5. Which kernel executes it?
6. Does the target NPU have efficient support?
