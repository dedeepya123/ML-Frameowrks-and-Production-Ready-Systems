# Module 5 — Part 3: Where Do We Quantize?

## Three Important Tensor Categories

1. Weights
2. Activations
3. KV cache

## Weight Quantization

Weights are fixed after training.

Can quantize offline and store compactly.

Examples:

W8A16
W4A16

Benefits:
- lower model memory
- lower weight bandwidth

## Activation Quantization

Activations depend on input.

Examples:

W8A8

Benefits:
- lower activation memory
- potentially efficient integer compute

Costs:
- activation quantization
- calibration
- quantization error
- runtime overhead

## W4A16

Weight = INT4
Activation = FP16

Main benefit:
large weight-memory/bandwidth reduction.

Execution depends heavily on the kernel/hardware.

## W8A8

Weight = INT8
Activation = INT8

Can enable efficient INT8 matrix computation.

Requires good activation quantization and hardware support.

## Per-Tensor

One scale for entire tensor.

Pros:
- simple
- less metadata

Cons:
- may represent different channels poorly

## Per-Channel

Different scale for each channel.

Pros:
- better representation
- often better accuracy

Cons:
- more metadata
- more complex kernel/runtime handling

## Production Reasoning

Never say only:
"Model is INT8."

Ask:

What is quantized?
Where?
With what granularity?
What kernel executes it?
What is the accumulator?
What does the NPU support?

## Key Principle

Quantization is usually selective.

A production model can contain:
- FP16 tensors
- INT8 tensors
- INT4 weights
- quantized KV

at the same time.
