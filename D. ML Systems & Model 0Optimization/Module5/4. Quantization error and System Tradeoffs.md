# Module 5 — Part 4: Quantization Error + Systems Tradeoffs

## Quantization Error

Original:
x

Quantized/reconstructed:
x_hat

Error:

e = x - x_hat

Lower precision generally increases potential quantization error.

## Why INT4 Is Harder Than INT8

INT8 → ~256 representable levels
INT4 → 16 representable levels

Fewer levels → coarser representation → potentially larger error.

## Error Is Distribution-Dependent

Different layers/channels can have different value distributions.

Outliers can make global quantization less effective.

This motivates:
- per-channel
- per-group
- calibration
- outlier handling
- mixed precision

## Accuracy

Quantization changes:

Y = XW

into approximately:

Y ≈ X W_hat

Errors can propagate through layers.

Therefore accuracy validation is required.

## Quantization Is a Tradeoff

Benefits:
- memory ↓
- bandwidth ↓
- potentially compute ↑

Costs:
- numerical error
- quantization/dequantization
- runtime complexity
- kernel requirements
- possible accuracy degradation

## Roofline Connection

If workload is memory-bound:

precision ↓
→ bytes ↓
→ bandwidth pressure ↓
→ arithmetic intensity ↑
→ potentially better performance

If compute-bound:
memory reduction alone may provide limited benefit.

Hardware low-precision compute support becomes critical.

## Three Questions

For any quantization optimization ask:

1. Does it fit?
2. Is it accurate?
3. Is it faster?

A quantized model must be evaluated end-to-end.

## Compression vs Acceleration

Quantization can reduce model size
without necessarily accelerating inference.

Acceleration requires:
- suitable hardware
- efficient kernels
- favorable bottleneck
- low conversion overhead

## Core Principle

Quantization is an optimization hypothesis,
not a guaranteed performance improvement.
