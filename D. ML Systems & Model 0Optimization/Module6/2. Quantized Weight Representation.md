# Module 6 — Lesson 2: Quantized Weight Representation

## INT8

FP16 weight:
2 bytes/value

INT8:
1 byte/value

Representation:

INT8 values + quantization metadata

---

## INT4

4 bits/value.

Two INT4 values can be packed into one byte.

Therefore:

INT4 ≈ 0.5 byte/value

But actual storage also includes:
- scales
- zero-points if used
- grouping metadata
- packing/layout information

---

## Group-wise Quantization

Weights are divided into groups.

Each group can have its own scale.

Smaller groups:
- better numerical resolution
- more metadata
- more scale handling

Larger groups:
- less metadata
- simpler implementation
- potentially more quantization error

---

## Checkpoint ≠ Runtime Representation

A checkpoint may contain:

INT4/INT8 values
+
scales
+
metadata

Runtime may transform them into:

packed/reordered/kernel-friendly representation.

Therefore:

Model representation
→ checkpoint
→ runtime representation
→ kernel representation
→ NPU

may involve several transformations.

---

## Important Questions When Reading Code

1. What is stored?
2. What is the dtype?
3. Is it packed?
4. Where are scales stored?
5. What is the group size?
6. What axis/grouping is used?
7. Does runtime reorder/pack it?
8. What kernel consumes it?
9. What representation reaches the NPU?

## Core Mental Model

"INT4 weight" is not just an integer tensor.

Think:

values
+ scales
+ metadata
+ packing/layout
+ runtime/kernel interpretation.
