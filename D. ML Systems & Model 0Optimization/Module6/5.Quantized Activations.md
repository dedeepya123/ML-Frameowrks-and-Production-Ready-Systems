# Module 6 — Lesson 5: Quantized Activations

## Activation

An activation is a tensor produced during inference.

Example:

hidden_states
    ↓
Q/K/V projection
    ↓
activation tensors

---

## Activation Quantization

FP16 activation
    ↓
choose/use scale
    ↓
divide by scale
    ↓
round/clamp
    ↓
INT8 activation

Mathematically:

X ≈ sx × Xq

---

## Weight vs Activation Quantization

Weights:
- fixed after model deployment
- can be quantized offline
- reused for many requests

Activations:
- depend on input
- produced during inference
- quantization can introduce runtime overhead

---

## Weight-Only Quantization

Example:

W4A16

Weight → INT4
Activation → FP16

Benefits:
- weight memory ↓
- weight bandwidth ↓
- no activation quantization required

---

## Weight + Activation Quantization

Example:

W8A8

Weight → INT8
Activation → INT8

Potentially enables efficient low-precision GEMM.

But activation quantization introduces:
- computation
- memory movement
- scale handling
- possible accuracy loss

---

## Activation Scale

Possible approaches:

Static:
calibration → scale → inference

Dynamic:
activation → determine scale → quantize

Dynamic approaches can adapt better but may add runtime overhead.

---

## Full Quantized Path

FP16 activation
      ↓
activation quantization
      ↓
INT8 activation
      ↓
INT8 × INT8
      ↓
INT32 accumulation
      ↓
scale / conversion
      ↓
output

---

## Systems Insight

Do not evaluate only:

"Is INT8 GEMM faster?"

Evaluate:

activation quantization
+ GEMM
+ accumulation
+ conversion
+ memory movement
+ scheduling

End-to-end performance matters.

---

## Four Levels

Model:
Linear(x)

Tensor:
FP16 activation → INT8 activation

Compute:
quantization + INT8 GEMM + accumulation

System:
runtime → kernel → NPU

---

## Core Principle

Quantization can change the tensor flow around an operator,
not just the weight stored inside the operator.

High-level model semantics remain the same;
runtime/compiler determines the executable implementation.
