# Module 6 — Lesson 6: Quantized KV Cache

## Why Quantize KV Cache?

KV cache creates two major pressures:

1. Memory capacity
2. Memory bandwidth during decode

Lower precision reduces bytes stored/read.

---

## FP16 → INT8

FP16:
2 bytes/value

INT8:
1 byte/value

Raw KV storage can be approximately halved
(excluding scale/metadata overhead).

INT4:
0.5 byte/value

Raw storage can be approximately 25% of FP16.

---

## Quantized KV Representation

Conceptually:

K ≈ sK × Kq
V ≈ sV × Vq

Cache contains:

Kq + scale information
Vq + scale information

Exact layout/granularity is implementation dependent.

---

## Important

Quantized storage does NOT necessarily mean
the attention computation is entirely performed
in that same precision.

Storage precision ≠ necessarily compute precision.

A kernel may load compressed K/V and perform
higher-precision internal computation.

---

## Naive vs Optimized

Naive:

INT8 K/V cache
    ↓
dequantize
    ↓
FP16 K/V
    ↓
attention

Potentially creates extra memory traffic.

Optimized:

INT8 K/V
    ↓
quantized-aware attention kernel
    ↓
attention computation

Logical dequantization does not necessarily
mean a separate materialized tensor.

---

## Runtime Cost

New K/V during decode:

compute K/V
    ↓
quantize
    ↓
store in cache

This adds runtime overhead.

But those cache entries may be read many times later.

Tradeoff:

quantization overhead now
vs
memory/bandwidth savings later

---

## Accuracy Tradeoff

KV quantization:

K/V approximation
    ↓
attention score perturbation
    ↓
attention output perturbation
    ↓
possible quality loss

Therefore accuracy validation is required.

---

## GQA + KV Quantization

GQA:
reduces number of KV heads

KV quantization:
reduces bytes per KV element

They attack different dimensions of KV-cache memory
and can potentially be combined.

---

## Systems Questions

When seeing quantized KV cache ask:

1. What dtype is stored?
2. What are the scales?
3. What is the quantization granularity?
4. When is K/V quantized?
5. Where is the cache stored?
6. What layout is used?
7. What attention kernel consumes it?
8. Is dequantization materialized?
9. What precision does the kernel compute with?
10. Is the memory/bandwidth saving worth the quantization overhead?

## Core Principle

KV quantization is primarily a memory/bandwidth optimization,
but its actual benefit depends on the entire decode path.
